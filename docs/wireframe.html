MIDI 编辑器线框

两个窗口：编辑器（编辑 + 试听）和演奏器（把音符转成鼠标键盘输入）。卷帘固定显示 4 小节、不缩放，靠下方导航条定位。紫色标注是设计决定。

1固定 4 小节，不缩放

每屏恒定 4 小节，窗口变宽是每小节变宽（不是显示更多小节）。没有缩放级别，手有肌肉记忆，一屏就是 4 小节。代价是密集段落点不准 —— 用第 2 条解决。

2键盘微调替代缩放

点音符不需要点准，选中后 ←→ 挪时间（按 16 分音符）、↑↓ 挪音高、Shift+←→ 改时值。概览交给固定视图，精确交给键盘，两者不互相拖累。

3导航条按小节吸附

下方那条是整曲缩略图，柱子高度＝该小节音符多少，所以看密度就知道副歌在哪。拖动时吸附到小节线，不会停在半小节上，而且拖动过程中红线（播放头）会隐藏——不然它跟着吸附一格格跳，很烦。松手后红线回到落点。右边那格是位置：播放头在第几小节，不是视口起点——视图范围那串「第 1–4 小节 / 共 24」整条删了，缩略图上的视口框已经把「我在看哪一段」说过了，文字是同一件事说第二遍；而位置读数挨着「跳到」，两个数摆在一起才是「我在哪 / 我要去哪」的对照。再右边可以直接输入小节号跳过去。

4按播放看它自己流过去

播放时视图连续滚动，把播放头保持在屏幕左侧约 1/3 处（留出前瞻）。停止时视图自动对齐到小节线——你按停止就是要改东西，不该让你面对半截小节。把速度改成 152 再按播放，播放头会走两倍快。

5垂直方向也固定

每条轨行高恒定，并且只显示这条轨实际用到的音域（自动裁到最低音到最高音）。所以一个只用 8 个音的贝斯轨不会白占 3 个八度的高度，4 条堆叠也塞得下。

6一套读数，不是两套

鼠标移到音符上，读数条一次给全五格：轨 / 音高 / 小节 / 拍位 / 时值（音高写音名 + 简谱，如 G4（5））——需求 1.5 要的是这些，从前却拆成左右两套：「悬停」那套给音高 / 小节 / 拍位，「选中」那套给轨 / 时值，同一个音在两处各显示一半，鼠标一移开左边变空、右边还留着，看着像两台机器。现在的规矩只有一条：悬浮的音优先，没悬浮就用主选中的音。

两个都没有的时候，这五格连标签一起藏起来（不是显示一排破折号）——「还没载曲子」和「载了但没悬停」是同一件事，不该一个一排 —、一个整块消失。外面那条读数栏的高度不动（min-height），否则鼠标一划过去整窗就跳一下。

线框里只有悬停这一路（它不实现拖动和选中），所以鼠标一移开就整块消失；「回落到选中」那半条路只能在真程序里看。

7删除某一段落

在卷帘空白处横向拖拽框出一段时间，弹出「删除选中段落」。五个参考仓库里没有一个实现了这个，是全新功能。

8BPM 是数字，不是百分比

写 76，单位是拍/分。音符内部存 tick，改这个数字只改开头那一个速度值，音符本身一动不动。

9变调是每条轨的偏移量

改这个值不改动音符，只在播放和导出时应用。可以随便拖、随时归零，不会毁掉原曲。鼓轨不适用（打击乐没有音高）。

10播放留在编辑器，演奏搬出去

底部播放条保留（改完能马上试听）。演奏那套搬到了右上角「演奏器…」打开的独立窗口。

11工具栏收成两组菜单

「文件」= 导入 MIDI… / 保存（Ctrl+S）/ 另存为… / 导出；「操作」= 撤销（Ctrl+Z）/ 重做（Ctrl+Y）。分组按的是这件事是什么，不是「谁常用」：一组进出盘，一组动谱面 —— 以后新增的编辑类动作往「操作」里加，工具栏的宽度一分都不用再让（原来四颗文件按钮 + 曲名框已经快把这一行占满了）。线框里这两颗点不开：没有弹出层的样式，硬开出来只会是一块没长相对齐的列表。

快捷键印在菜单项右边，不是 ToolTip：菜单的标准做法，鼠标不用停下来等。它只负责显示 —— 真按键是窗口级接的（焦点在输入框里时让开，不然打字会变成按命令）。

「演奏器…」不进菜单，留在右上角当独立按钮：它是「去另一个窗口」，不是文件操作；而且演奏是这个程序的正事，藏进两层菜单等于把它埋了。代价是导入不再是工具栏上那颗蓝按钮——菜单项没有「推荐」这个概念，这是菜单化明码标价的代价，接受它：启动第一件事还有两处指着（「文件」菜单本身，和空状态那句「还没有曲子 —— 把 .mid 拖进这个窗口，或从「文件」菜单导入」）。

12空格是播放 / 暂停

空格和走带条左边那颗按钮是同一颗切换键：放着的时候按 = 停在原地，停着的时候按 = 从那儿接着放（字变成「▶ 继续」）。两处说的是同一件事，所以按钮上的字和读数条那行提示必须一起改口 —— 这正是这一条值得单列出来的原因。

它推翻了一个从前的决定（那个决定写在 docs/prototype-聚焦轨.html 的 Q12 里，那儿照实改了）：从前空格只管「开始」，播放中按空格没反应。理由当时是成立的 —— 那时还没有「暂停」，两头只剩「放」和「停」，按第二下等于把刚放的东西丢掉，连按两下手确实会不知道自己站在哪一头。现在第二下的结果直接写在按钮上（▶ 暂停 → ▶ 继续），迷失不了，所以一个键管两头。

空格是窗口级收的，而且必须抢在控件前面：焦点停在轨头的按钮、下拉上时，空格本来归它们（按钮是「按一下」、下拉是「展开」），不抢就是「空格播放」时灵时不灵 —— 而屏幕上没有任何东西说得清为什么，人只会以为自己按歪了。输入框那一头整块让开（改名、速度、小节号、曲名），所以改名字时打空格还是空格。

两颗走带按钮因此都不在 Tab 序里：按钮的标准激活键正是空格，留着 Tab 位就等于摆一个「Tab 得过去、按空格却没反应」的落点，比一开始就不给这个落点更坏。鼠标、回车照旧能按。

13没有循环，放完就停

循环控件整个去掉了。发出去的是真实按键事件，循环失控等于往游戏里持续灌输入。播到曲尾自动停止，并主动松开所有按键和鼠标。

14看门狗兜底

去掉循环不等于安全——单次播放也会卡（F6 线程挂了、note-off 丢了）。所以：F6 挂在独立的低级钩子线程上，UI 卡死也能响应；另有一个硬超时，曲长 +5 秒后无条件停并松键。

15不读游戏进程

程序全程只做一件事：往系统里发按键。不枚举进程、不查前台窗口、不碰游戏内存。代价是没有「失焦自动急停」这条兜底（它需要知道谁在前台），发错窗口只能靠你在倒计时结束前切好。

16只发一条轨

游戏乐器同时只能响一个音，所以多轨可以一起播给你听，但发按键时只能挑一条。
「演奏轨」下拉框只列出单声部轨——判定看的是起音是否撞在一起（同一瞬间 ±30ms 内有两个音 = 和弦），不是看时值有没有重叠，否则连奏的旋律会被误判成多声部。
一条都没有时下拉框锁死，直接告诉你去编辑器删声部。

17悬浮倒计时，不抢焦点

你按下开始就会切到游戏，所以演奏器窗口本身看不见。倒计时必须浮在游戏画面上。悬浮层始终置顶，但绝不抢走游戏窗口的焦点（否则按键会发错地方）。

18启动前自检

点「开始演奏」前检查两件事：程序是否以管理员运行（否则按键会被系统拦掉）、输入法是否在中文状态（中文输入法会吞掉按键）。这两条是参考实现踩过的坑。没放行时说的不是一句「不能开始」，而是具体哪一种、下一步去改什么（权限不够就重开程序、输入法中文就切英文、轨弹不了就换轨）——说不清下一步的提示等于把人支到错方向上去，比不说更坏。

19常驻风险横幅删了

演奏器窗口底下那块横幅（「虚拟输入违反游戏规则，可能导致封号，风险自负」+「本程序只做一件事：往系统里发按键」）整块删掉，样式一起删。

代价是有意接受的：那是这个自用工具上唯一一句风险提示，以后给别人用就没这句话了。它不影响任何功能，而它占的是演奏器窗口里最显眼的一格 —— 每次都说着同一句、按一次「知道了」也消不掉的话，读到最后就是墙纸。

留下的那条「为什么没开始」的通道是状态行（上面那块 status）：它说的是这一按为什么没生效，横幅说的是用这个程序的后果，两件事，删的是后者。横幅里另外两件事没有跟着消失：「只发按键、不读进程」在上面标注 15，急停键 F6 写在「开始演奏」那颗按钮上（演奏前就该知道出事了按哪个）。
