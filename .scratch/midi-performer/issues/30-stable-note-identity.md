# 30: Note 稳定身份 + NoteRef 按身份寻址

**What to build:** 给音符一个**跨重排不变的身份**，选中集不再因为下标洗牌而失效。

**几处要说清楚的决定：**

- `NoteRef` 现在是 `(轨, 下标)` —— **下标寻址**。它自己的注释就写着这是
  「an address at that moment」，任何一次重排都让它作废，而且是**一声不吭地**作废：
  你手里的 ref 不会报错，它只是**指向了另一个音**。
- **代价已经漏到界面上了**：`MainWindow` 有一整套**平行的、按值的**选中集镜像
  （约 100 行：捕获选中音的内容、改完之后拿内容去 `Track.Notes` 里重新找、恢复下标）。
  它存在的**唯一原因**就是「模型没有稳定身份，界面只好自己拿内容去重新认音」。
  同一件事还在接口文档的**三处不同位置**被反复警告「重排后下标会变，界面得重新算选中集」。
- **做法**：给 `Note` 引入稳定身份（`NoteId`），`NoteRef` 变成 `(轨, NoteId)`。
- **要在这条工单里定下来并写进注释的几件事**：
  - **身份从哪来** —— 导入时按顺序分配。**同一次导入必须可重现**（全链对拍测试靠这个）。
  - **导出不带身份** —— 写出去的是标准 MIDI，没有地方放它；重新导入重新编号。
    这是可接受的，因为**选中本来就不跨文件重载存活**。
  - **工程文件 JSON 要不要持久化身份** —— **倾向要**，否则存盘再打开选中就没了。
    但既然选中本来也不跨重载存活，**不要**也说得通（少一个字段、少一份兼容负担）。
    **实现在这条工单里决定并说明理由。**
  - **编辑时身份不变**：挪动、改时值、改音高**都不换身份**；
    `CutRange` 剪出来的**新音分配新身份**（它们确实是新音）。
- **三处「重排后界面得重新算选中集」的警告随之消失** —— 这是这条工单的主要产出，
  和 28 号工单那种「删掉一段不需要的解释」是同一类收益。
- **依赖 28**：`Note` 的 JSON 读写现在埋在 1084 行的静态类里，
  **先拆出来改才是局部的** —— 否则一处改类型要在一个千行文件里翻。
- **依赖 29**：重排先在 `Track` 收口，30 才只需要处理「怎么认音」，
  而不是同时改「怎么排序」和「怎么认音」两件事。
- **界面不在这条工单里改** —— 那是 31 号工单。这条只让模型层**有能力**给出稳定身份。

**Blocked by:** 28, 29

**Status:** done —— 但只做了**模型那一半**：第 2、7 项没做，并进 31

- [x] `Note` 带有稳定身份，重排后身份**不变**
- [ ] `NoteRef` 按身份寻址，重排后旧 ref **仍然指向同一个音** —— **没做**，交给 31
- [x] 挪动 / 改时值 / 改音高**不换身份**；`CutRange` 剪出来的新音是**新**身份
- [x] 导入 → 导出 → 再导入，逐字段相等的全链对拍**仍然成立**
- [x] **同一次导入的身份分配可重现**（同样的输入两次导入得到同样的身份）
- [x] 导出写出的 MIDI 里**不含**身份信息

## 哪些是测出来的、哪些只是写出来了

**改了什么**：`Note` 多带第 5 个字段 `Id`（`NoteId`，默认 0 号 = 没身份）。
**发号的地方全链只有一处**（`NoteIdentity`），两条入口都从它取号：MIDI 导入
（`MidiReader`）和读工程文件（`SongProjectFile`）—— 同一份谱面从哪条路进来，号必须一模一样，
否则「存盘再打开」和「重新导入同一个 MIDI」会给出两套身份而没有任何东西会提醒你。
编辑命令写回时用的是 `note with { ... }`，只点内容字段，所以**身份自然跟着音走**；
`CutRange` 剪出来的碎片另说 —— 它从 `FirstFree`（这一轨现有最大号 + 1）取新号，
而且取号的范围是**剪之前**那一轨。`Converters` 可选读写信箱里的 `Id`，
工程文件读完会 `Normalized` 盘一遍（重号或全 0 就整轨重发）。
工程文件版本号**没动**，还是 1。

**最大的一件：第 2、7 项没做。**

`NoteRef` 还是 `(轨, 下标)`，`MainWindow` 那套按值的选中集镜像**一行没动**，
`ISongEditor` 里那两处 + `NoteRef` 自己那一处共三处「重排后界面得重新算选中集」的警告
**都还在**。这一条不是「没验」，是**没做**。

**为什么没做 —— 这张工单自己前后打架。** 「几处要说清楚的决定」里写着
「**界面不在这条工单里改** —— 那是 31 号工单。这条只让模型层**有能力**给出稳定身份」，
但验收第 2 项要求 `NoteRef` 换成按身份寻址。这两条不能同时成立：App 里有 10 处、
`PianoRollController` 里有 7 处把 `.Index` 当**数组下标 / int** 用（卷帘拖动的锚点、
拖动时的影子、悬停高亮、选中的轨内下标、按内容找回音符之后的落点），
只改模型那一半，整个解决方案**编不过**。硬凑（让 `Index` 索性返回身份号）更糟 ——
那会让界面把身份当下标使，又变成一声不吭地指错音。
所以按「决定」那一半收口，第 2 项并进 **31**：31 本来就要删掉 `MainWindow` 那套镜像，
而「`NoteRef` 按身份寻址」和「界面不再拿内容重新认音」本来就是同一件事。
`NoteRef` 的注释里把这段理由写下来了，下一张工单的人不必再推一遍。

第 7 项同理：三处都**改写**了（加了「这一句现在仍然成立，理由是……」），
但**没有删除** —— 因为第 2 项没做，这三句话仍然是真话。按字面「删除**或**改写」算做到了，
按这张工单的本意（身份到手之后这三句不再需要）**没做到**。所以这一格不打勾。

**机器测过的：**

- 全套 **1594 条测试绿**（19 号之后是 1570，这条工单 **+24**）：
  `NoteTests` 一批新的、`SongEditorNoteCommandTests` 九个、`SongProjectReadTests` 三个。
- **同一次导入读两遍身份一模一样**，而且**一轨一数**（1..N）；语料里每一条轨的身份都是 1..N。
- 挪动 / 改时值 / 改音高身份不换 —— 含**越过邻居重排之后身份还跟着那个音走**这条
  （重排是 29 号收口进 `Track.WithNotes` 的，这里量的是重排之后号没跟着下标跑）。
- `CutRange`：左截是新身份、伸出去又挪回来的那截是新身份、整体前移的不换身份、
  新号从**现有最大号**往上发（不是数一数有几个音）。
- 工程文件：**存盘再打开身份不变**；老工程没身份时按位置重发 1..N；
  文件里重号时**整轨重发**。
- **导出不带身份**：`MidiWriter` 里 `Id` 一个字符都没有 —— 这条是 grep 出来的，不是跑出来的，
  但结论比跑出来的更硬（写出去的东西不看这个字段，是结构性的，不是这一次碰巧没写）。

**跑起来量过的**：**没有**。这条工单没碰界面，app 一眼都没跑 —— 这是它自己的范围
（「界面不在这条工单里改」），不是漏了。

**没验的，按风险排：**

1. **全链对拍对身份是瞎的。** `Note.Equals` **故意**不比 `Id`（理由写在那个方法上：
   MIDI 里没有地方放身份，导出丢、导入重发，「这两份谱面是不是同一份」不该被身份发得一样不一样
   决定）。后果是「导入 → 导出 → 再导入逐字段相等」这条**不管身份发得对不对都会绿** ——
   它验的是谱面，不是身份。第 4 项那一格是这么打上勾的：条件是满足了，
   但它**对身份什么也没说**。要真验得在「导出后再导入」的那一份上单独比号，没做。
2. **「老工程没身份 → 按位置重发」只有文件顺序升序时才和「重新导入同一个 MIDI」对得上。**
   读工程文件端按**文件里的顺序**发号，导入端按**起始 tick 排序后**的顺序发号。
   手写过或改过的 `.mproj` 里音符顺序乱了，两条路给出的号就不一样，
   而且**不会报错**。真实文件（本程序写出去的）永远是升序，所以这条风险只落在手改的文件上。
3. **`FirstFree` 会重发刚删掉的那个号。** 删掉号最大的那个音之后再剪一刀，
   新碎片拿到的正是刚删掉那个号。注释里认了这个代价（那时候那个号已经没有合法持有者），
   但「旧曲子还压在撤销栈里」这类持有者是不是真的都无害，**没验**。
4. **手工拼出来的 `Song` 存盘再读回来，身份会变成 1..N。** 盘上没有 `Id`，
   `Normalized` 整轨重发。**31 要知道这件事** —— 它要是拿身份当跨重载的把手，这条会咬人。
5. **旧版程序读新文件**：文件里多了 `Id` 字段，旧版会不会崩 —— 只是按既有的
   「文件里多出派生字段也能读回来」那一条**推断**的，没真的拿旧版跑过。

> **记一条关于写工单的：** 这张工单的「决定」和「验收」互相矛盾（决定说界面不改，
> 验收要求只有改界面才做得到的东西）。Agent 撞上这个之后按「决定」收口、把冲突上报，
> 这个处理是对的 —— 但代价是一张工单交付了一半，而且**验收格子上看起来像没做完**。
> 下次拆这种「模型先有身份、界面后用身份」的活儿，**要么**直接写成一张
> （模型 + 界面一起动，31 那套镜像本来就得同时删），**要么**把模型那一半的验收写成
> 「模型有能力给出身份，且给了测试」，别把「谁在用这个身份」写进同一张的验收格子里。
