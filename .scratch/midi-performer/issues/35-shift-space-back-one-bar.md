# 35: Shift + 空格 = 回跳一小节并播放

**What to build:** 一个新动作：**播放头退回一小节的小节头，然后立刻开始放**。绑在 **Shift + 空格** 上。

用户原话（2026-09-20）：

> OK，再增加一个工单，增加一个功能："回跳上一小节并播放"。
> 然后绑定一个快捷键。我还没想好哪个快捷键比较顺手，但是这个是很经常用的功能，
> 所以我希望它会比较顺手，比如说双击空格或者什么之类的。

**几处要说清楚的决定：**

- **键选 Shift + 空格**（2026-09-20 问过用户，四个选项：双击空格 / Shift+空格 / 回车 / F7）。
  用户选了 Shift+空格，并且**专门叮嘱了一句**：
  > 那就 Shift+空格吧。但是你要注意啊，空格还是播放和暂停的切换，然后 Shift+空格是快速回调上一小节并播放。

  所以这一票的判据里有**一半**是在钉「空格没变」（`verify-35.ps1` §2，用**普通空格**量）。
  当初没选「双击空格」的理由记在这儿：区分单双击要么给单次空格加一个时间窗口的延迟
  （而空格是全程序最常用的键），要么让第一下先真的切一次播放状态（正在播时就是一个断口）；
  而且「连按两下空格」今天的意思是「暂停 → 继续」，改它就是给一个既有手势改义。
- **落点 = 当前小节 − 1 的「小节头」**（问过用户，另一个选项是「先回本小节头、已在小节头才往回跳」）。
  练琴的用法是「这一小节弹糊了，退一小节再来」—— 退的是**整整一小节的预备**。
  播放头停在第 8 小节第 3 拍时按一下 → 从第 7 小节头开始放。
- **第 1 小节按 = 回第 1 小节**（夹住）：`TickOfBarClamped` 自己把 −1 夹成 0，
  和「跳到 __ 小节」框、和 ↻ 是**同一把夹子**。这一条有 §4 专门钉（防的是读数变成 0 或整条没了）。
- **不加走带条按钮**（问过用户，两个选项是「加一颗 ↺ 上一小节」/「不加，只要快捷键」）——
  用户选了**不加**。所以这个功能的可见入口只有读数条那行提示（下面那条「知道代价」有实测数）。
- **和 ↻ 共用「寻到某小节 + 起播」那一半**：`RestartPlayback()` 成了 `SeekBarAndPlay(0)`，
  新的 `BackOneBarAndPlay()` 是 `SeekBarAndPlay(当前小节 − 2)`。
  「不做 `Stop()`」「不硬写 `SeekSeconds`」那两条理由都搬到了 `SeekBarAndPlay` 上，一处一份。
  中间那个减 2 不是笔误：`BarOfTick` 给的是**1 起**的小节号，`TickOfBarClamped` 收的是**0 起**的。
- **「能不能放」以播放键的灰为准**（`PlayButton.IsEnabled`），和空格那一支同一句话。
  ↻ 本来就有这道闸门（按钮灰着点不动）；**Shift+空格 是按键，绕得过按钮的灰**，
  所以这道闸门是这一票**新写的**，不是顺带有的 —— §0 专门量它（没装曲子时按下去什么都不做）。
- **「把焦点从按钮上收回来」提成了 `ReleaseControlFocus()`**（空格和 Shift+空格 共用）。
  那一下的来路写在它的 doc 里（实测：焦点停在轨头「折叠」上按空格，轨收起来了**而且**开始播放）。
  抄一份就是第二处规矩 —— 新加的那一支要么漏了它、要么抄错，症状都是「一个键干了两件事」。
- **提示行加一条，放在「空格 播放/暂停」旁边的位置**（两个空格手势挨着）。
  **知道代价**：那行窄了会被省略号从右边截掉（26 号的设计）。实测（`.scratch/probe-35-hint.ps1`）：
  这段文字的**自然宽度 1959 物理 px**（不装曲子、没有读数栏时量的，那时框 2254 宽、装得下），
  而**装了曲子、读数栏在场时那个框只有 1486 物理 px** → 默认窗口下看得见约 **76%**，
  尾巴上约 **24%** 被截。排在前面，所以**这一条看得见**；被挤出去的是末尾那几条 ——
  按宽度比例推，切在「Delete 删除」附近，`Ctrl+Z` / `Ctrl+Y` 落到截掉的那一头
  **而那两条本来就在「操作」菜单里再说一次**（`verify-26.ps1` §6 量着：菜单里右侧写着 `Ctrl+Z` / `Ctrl+Y`），
  所以这一处的净损失是「少了一条屏幕上的说法」，不是「键位在屏幕上消失了」。
  全文永远能从提示行的 ToolTip 看全（26 号那句「一句喂两处」还在）。
- **改了提示行就要跟着改四处**（26 号留下的那条线）：`FormatTests.快捷键提示逐字就是屏幕上那一行`（逐字）、
  `FormatTests.提示里一条都不缺`（+ 一条 Contain）、`ShortcutHintTests.HintToBinding`（+ 一对）、
  `verify-26.ps1`（`$预期` + 那串片段）、`docs/wireframe.html` 的 `.hint`。
  这一票五处都动了，**没有一处是「顺手」改的**。
- **`ShortcutHintTests` 那一对新加的判别式挑的是 `Key.Space && shift` + `BackOneBarAndPlay()`**：
  左边光写 `Key.Space` 的话，把这一支删掉、空格那一支照样在，那条会假绿；
  右边光写方法名的话，把它绑到裸空格上（= 空格变成回跳、播放/暂停没了）也是绿的。

## 哪些是测出来的、哪些只是写出来了

**测出来的**（真机、真窗口、UIA 读控件；log 在 `.scratch/verify-35.log`）：

- **「退了一小节」和「在放」是分开量的**，缺一条都不够：只量「按钮变成 ⏸ 暂停」的话，
  一个「什么都没退、只是开始放」的实现照样绿；只量位置的话，「退到了但停在那」也能过 §1 的前半句。
  所以每条都读了两次位置（按下后 180 毫秒、再过 3 秒）。
- **三态各试一遍**：正在播（§1）、暂停中（§3）、已放完（§5）—— 进来的状态不同，
  只试一种的话「暂停中按完卡在『▶ 继续』上」这种错看不出来。
- **§2 用的是普通空格**，不是 `Invoke` 播放键：这一票有把空格抢走的可能，
  拿播放键的 Invoke 去量就绕开了这个风险（33 号那次教训：空格是窗口级、播放键是按钮级，覆盖不到）。
- **§0 是刚起的干净实例**（还没载曲子），量的就是那道新写的 `PlayButton.IsEnabled` 闸门。
- **提示行的宽度是真的量了像素**：`.scratch/probe-35-hint.ps1` 截那一行、逐列找墨迹
  （不装曲子时框 2254 宽、墨迹 1959 宽 → **没被截**，这个 1959 就是这段文字的自然宽度）。
  装着曲子时那个框只有 1486（33 号那轮量的）—— 两个数一比才有那个 76%。

**只是写出来了、没测到**：

- **被省略号截掉的到底是哪几个字**：**只能按宽度比例推**（切在「Delete 删除」附近）。
  UIA 读到的永远是全文（`TextTrimming` 只影响渲染），26 号那轮就栽在同类事情上。
  想知道确切边界只有一条路：**看 `.scratch/shot26-full.png` 那张图**（那是装着曲子、默认窗口下截的）。
- **「落点在小节头」这半句**：位置读数只能给到「第几小节」，给不到「小节内的第几拍」。
  能作证的只有「180 毫秒后读到的还是退回去的那一小节」—— 那是**和这个判断一致**，不是证明它。
- **`Shift+空格` 在别的输入法 / 别的键盘布局下**：没量（脚本打的是裸的 Shift+Space）。
- **不加按钮之后，这个功能能不能被用户发现**：这是设计上知道的代价（见上面那条），不是能测的东西。

## 给下一个人的坑

1. **`BarOfTick` 是 1 起、`TickOfBarClamped` 是 0 起**，「上一小节」中间那个 **− 2** 就是这个换算。
   写成 − 1 的话退的是**本小节**（症状是「按了像没按」—— 因为你才刚从小节头附近过来），
   写成 − 0 就是原地重播。这一条最容易改错，因为三种写法都编译得过。
2. **这一票量的「上一小节」是相对「按下去那一刻的播放头」**，不是相对「上一次跳小节跳到的那一小节」。
   `verify-35.ps1` §1 第一版就是把预期写成了后者（写死 19）而红的 ——
   那时播放头已经往前走了 2 秒（22），它退的是 22 那一格（21）。**红的是预期，不是 app。**
   所以要按「读数 − 1」判，不要按「上一次跳到的 − 1」判。
3. **提示行那一条排在「空格 播放/暂停」旁边，不是排在末尾。** 那行会从右边截——
   排末尾的话，第一个被截掉的就是这一条新键位（而 26 号的原话是「一条快捷键要是屏幕上没有一处
   说得清它，就等于没有」）。现在被挤出去的是尾巴上那两条，而它们在「操作」菜单里还有一处。
4. **改了提示行就要动五处**：`Format.cs`、`FormatTests`（逐字那条 + 片段那条）、
   `ShortcutHintTests.HintToBinding`、`verify-26.ps1`（`$预期` + 片段数组）、`docs/wireframe.html`。
   少改一处的症状是「测试红在一句和这票无关的话上」，别去改那句话，去补漏的那一处。
5. **想给它加按钮的话，位置在 `↻ 重头播放` 左边**（用户这一票选了不加，加是另一张工单的事）。
   加的时候记得 `RefreshTransport` 里的可用性判据要和播放键**同一句**（33 号定的规矩）。
6. **`ReleaseControlFocus()` 现在有两个调用点**（空格、Shift+空格）。以后再加「窗口级按键」，
   起手先调它 —— 不然焦点停在按钮上时，一个键会干两件事，而屏幕上什么都看不出来。
