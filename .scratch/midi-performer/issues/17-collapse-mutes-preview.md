# 17: 折叠起来的轨在试听里不出声（「折叠的声音也要跟着收」）

**What to build:** 15 的折叠是**纯眼睛上的**（「先不看它」，播放一个字节都不碰）。
这一条把它改成「**收起来的就是不听的**」：一条轨折起来之后，试听里它的音一个都不发；
展开回来照旧。别的什么都不动 —— 谱面、选中集、导出、发给游戏那一路，一个字节都不碰。

**几处要说清楚的决定：**

- **认轨用的是模型自己那对唯一键 `(TrackIndex, Channel)`，不是下标。** 和 15 里
  「重建之后按轨的身份把折叠带回去」取的是同一套。下标会随删轨整体前移 ——
  按下标静音会静到别人头上，而这一次那个错是**听得见的**。
- **折叠的轨连声道名额一起让出来**（`Mix` 里那个 `next++` 不为它走一格）。
  折叠的含义是「这条轨不在试听里」，它不该还占着一个声道的音色、把后面的轨往
  「>15 条就得共用声道」那一步推。跳过放在换算之前 —— 静音轨的音符没必要还走一遍移调与秒换算。
- **播着折叠是「接着放」，不是「停下来」。** 用户要的是「这条别响了」，不是「整遍重放」。
  这一条和换谱面（`Load`，会停）分开走：`PreviewPlayback.SetMutedTracks` 先把积分推到此刻、
  松开所有正在响的音、再从当前音乐时间把新那张表排一遍。**光换掉内部那个列表是不够的** ——
  出声那头手上还留着上一批音，被静音的那条轨会一直响到它自己结束。
- **那一行小字写「已折叠 · 不发声」**（wireframe 里只有「已折叠」）。折叠现在不只看不见、
  还听不见，而这一行是屏幕上唯一说得出这件事的地方；不写的话，用户只会觉得这条轨莫名其妙哑了。
  折叠按钮的悬停提示同步改了（原来那句「内容一个字节都不动」已经不准了）。
- **折叠**不跨曲子漏过去**：`SyncLanes` 那条重建分支里，同一首曲子的新一份（编辑 / 撤销）
  照旧按身份把折叠带过去，**换一首曲子（`rebuildAll`）一律不带**。从前的漏法最多是屏幕上
  一条轨莫名其妙收着；现在还兼着静音，漏过去就成了「打开一首新曲子，某条轨是哑的」。
  代价写在下面（重新打开当前这首也会把折叠摊平）。
- **Ctrl + ←/→ 跳到一条收起来的轨上，会把它展开并放回试听里**（`Reveal()`）。
  这一下是 15 定的（「跳过去了总得让人看见」），现在展开顺带也让它重新出声 ——
  两条是一件事的两面：用户找过去的那条轨，就该看得见、听得见。
- **只影响试听。** 演奏器是**另一个窗口、自己开自己的文件**（它不知道编辑器里谁收着），
  导出写的是模型，`.mproj` 里也不记折叠 —— 折叠仍然只是「这一次我这么看」，
  和「独奏」不是一回事（「只看这条」还是没做，右边那句灰字照旧）。
- **状态还是住在控件上**（15 定的），窗口那一侧不另存一份：`MutedTracks()` 每次现问一遍控件。
  抄一份出来就有两处要一起改，而它们迟早会不一致。
- **spec 第 23 条补了一句**：那条原来只写「折叠起来屏幕放得下」，现在折叠还兼着不听，
  两个目的都在那一句话里说了。改的是需求文档，不是代码 —— 不认这个目的的话改回去就行。

**Blocked by:** 15（折叠本身）、16（试听那条链的现状）

## 哪些是测出来的、哪些只是写出来了

**机器测过的（新 11 条，全套 1516 条全绿，编译 0 警告 0 错误）：**

- `PreviewMixerTests` 新增 5 条：静音的轨一个音都不发、其余的照旧 / **按轨块与声道认轨
  不是按列表下标**（这条就是按下标写会错的地方）/ 静音的轨不占声道名额 / 全都静音摊出空表 /
  名单里写了不存在的轨时谁都不静音。
- `PreviewPlaybackMuteTests` **新开一个文件，6 条** —— 这是 `PreviewPlayback` 第一次
  进机器测试（从前那层是「winmm 出声没法断言」，而 `FakeAudioSink` / `FakeClock` 两个假件
  一直摆在那儿没人用）。缝开在 `IAudioSink` 上之后，量得动的是**「这一下之后声卡又收到
  一批什么音」**：折叠正在播的轨是接着放不是停下来（`PlayCount` +1、`StopCount` +1、
  表里少一条、`IsPlaying` 还是 true）/ 重排是从此刻的音乐时间接下去不是从头（时钟走 0.5 秒，
  声卡收到 0.5）/ 展开回来那条音又回到表里 / 没在播的时候不碰声卡 / 还没装曲子时什么都不做 /
  全都折叠之后声卡收到空表。
  顺带量到：`DispatcherTimer` 在无头测试进程里建得起来、也不炸 —— 这条路原本以为走不通。

**跑起来量过的**（.scratch/uia-check4.ps1 / uia-check5.ps1，走 UI Automation 量控件状态）：

- **播着折叠一条轨，试听没被打断**：按播放 → `播放键可用=False 停止键可用=True`；
  折叠第一条轨（悬停提示量到是 `把这条轨收成一行，试听时不再出声（谱面一个字节都不动）`）→
  `已折叠 · 不发声` 出现 1 处、那一颗按钮变成「展开」，而走带条仍旧是
  `播放键可用=False 停止键可用=True` —— 也就是说这一下**没有**走出「正在播」那个状态。
  再展开回来：那一行收回去了、按钮变回「折叠」、仍旧在播。按停止回到 `播放键可用=True`。进程一直在。
  （量的是**接线**：`CollapseChanged` → `MutedTracks` → `SetMutedTracks` 这一条有没有把人摔下来。
  出声本身 UIA 断不了。）
- **折叠不跨曲子漏过去**：收起第二条轨（`折叠, 展开, 折叠, 折叠`）→ 从曲库里再打开当前这首
  （点那一行 + 回车，走的是 `LoadSong` → `rebuildAll: true` 那条路）→ 重新装完是
  `折叠, 折叠, 折叠, 折叠`、`已折叠 · 不发声` 剩 0 处。**这一条同时量到了上面那条代价**：
  重新打开当前这首，折叠也会被摊平。

**没验的，按风险排：**

- **「真的不响了」没有听过的证据。** 这一条从头到尾没有一处能让机器确认声音本身：
  Core 那一层验的是「表里没有这条轨的音」，`PreviewPlayback` 那一层验的是「这一下之后
  声卡收到的那批音里没有它」，而**生产用的 `WinmmPreview` 在这两件事之外还有一段**
  （`BuildEvents` → 调度线程 → `midiOutShortMsg`）。那一段一行没动过（16 里也是「不测」的那一类），
  所以「表对了声音就对」这条推理是**架在它没毛病上**的，不是我量到的。
- **`SetMutedTracks` 那一下会不会听出「咔」**：先 `Stop`（16 个声道各发一条 All Notes Off）
  再 `Seek` + `Play`，这中间有一个很短的空档，正在响的音会被掐掉。听感上是否可接受没听过。
  同一时刻恰好起音的音可能被切掉半个 —— 没量。
- **重新打开当前这首会把折叠摊平**（上面那条代价）。这是**行为变了**：15 那一版下
  重新打开是保得住折叠的。判断是「打开一首曲子 = 从头开始看」更不容易出意外
  （尤其现在折叠还兼着静音），但没问过用户是不是宁愿保住。
- **「收起来的轨看得出它不响」只到那一行字的程度**：卷帘上收起来之后什么都不显示
  （15 就是这样），这一行现在多写了「不发声」四个字。字体 10.5px、放在那根压扁的条左边，
  挤不挤、看不看得清没有量。
- **>15 条旋律轨 + 折叠**：单测钉住了「静音的轨不占名额」，但真播起来是另一回事（16 里
  也留着这一条）。
