## 落了什么

`SongProject` 上加了和 `Read` / `ReadBytes` 对称的 `Write(Song, string)` 与 `WriteBytes(Song)`；
测试在 `MidiPerformer.Tests/Project/SongProjectWriteTests.cs`（110 条）。

- 移调只在这里叠加：写出去的音高 = `Note.Pitch + Track.Transpose`，`Note` 一个字节都不动。
  越界的音高**夹到 0..127，不跳过**（取舍见 `ClampPitch` 的注释：导出物要被人编辑、被别的软件读，丢音不可逆；
  演奏那条路反过来是跳过不发）。
- 轨名、音色（`ProgramChangeEvent`）、速度（`SetTempoEvent`）、变拍（`TimeSignatureEvent`）一起写出去，
  速度与变拍统一放在第 0 个轨块（格式 1 的惯例位置）。
- 分辨率照 `TempoMap.Division` 写，PPQ 与 SMPTE（24 / 25 / 29 / 30）两种都能往返。
- 轨名按 UTF-8 写（DryWetMidi 默认是 ASCII，中文会被问号吃掉）。
- 写不出来的值（帧率不是四种之一、每帧 tick > 255、PPQ > 32767、轨块序号是负数）在门口抛中文 `InvalidDataException`，
  与读取端「分辨率 0 报中文错」对称。

## 「别的 MIDI 软件读得出来」这条怎么算验过

没法自动化，**代理是「导出 → 再导入读回同一个 Song」**。这个代理成立的理由：
读取端的能力已经由 `SongProjectReadTests` 对着原版 `MidiLoader` 和**文件里的整数 tick** 逐条钉过了
（轨数 / 轨块序号 / 声道 / 轨名 / 音色 / 每个音的 tick 与音高），所以「读得回来」等价于
「写出去的是一份标准形态、字段没错位的 MIDI」。另外 `写出去的文件里有轨名和音色事件` 这条不信我们自己的读取端，
直接换 DryWetMidi 按默认设置把字节读一遍，看那两个事件在不在。

## 两个坑（外加探到的第三个）

1. **`TrackIndex` 是「文件里第几个轨块」**，中间空掉的序号必须补一个空轨块（只有 EndOfTrack 的 MTrk），
   否则再导入时序号整体前移。做法：按 `TrackIndex` 分组，写 `0..max` 每一个序号，没有组可写的就是空轨块。
   语料里 63 份有 **18 份**踩到这条（格式 1 的第 0 块常常就是纯速度/版权轨）。
2. **同一轨块里多个声道共用轨名**：一组写一个 `SequenceTrackNameEvent`（取该组第一条）。
   格式 0 整首塞一个轨块靠声道分声部的曲子一定会走到，语料里 32 份。
3. **（实现时才发现的）兜底轨名是按声道算的，不是按轨块算的。** 文件里根本没写轨名时，
   导入端给每个声道各挂一个「声道 N」/「打击乐」，同组几条轨的名字**各不相同**；
   把兜底名当轨名写出去，再导入时整块都会挂上第一个声道那个名字（语料实测：「声道 16」回来变成「声道 7」）。
   做法：一组里每条轨的名字都等于它自己的兜底名时，一个轨名都不写，让导入端重新算一遍。

事件顺序也是这类坑：同一 tick 上**抬键排在按键之前**，否则「前一个音在这一 tick 结束、后一个音在同一 tick 开始」
会被配错（DryWetMidi 用 LastNoteOn 配对）。零时长的音是唯一的例外，它自己的抬键排在按键之后。
另外，同一 tick 上音符的先后顺序就是模型里的顺序，靠 `GroupBy` 的天然顺序（该声道第一次出音）还原。

## 修不掉的几处不对称（不是 bug，写在这儿免得下次当 bug 查）

- **格式没进模型**：`Song` 只装 tick，不装 SMF 格式。导出按「一个轨块 → 格式 0，多个 → 格式 1」写，
  格式 2 的曲子退化成格式 1（每个音原样保留，「各段各自计时」变成「同时开始」）。
- **没有音符的轨读不回来**：文件里它只是一条空轨块，而导入端的规矩是「没有音符的轨块不成轨」。
  「轨还在、音被删光了」这种 Song 导出再导入会少一条轨（轨名与音色仍留在文件里）。
- **同一个声道跨轨块**时，两条轨的音色在文件里各写各的，但我们的导入端按声道取全文件第一次切换，
  所以再导入时它们会得同一个值。
