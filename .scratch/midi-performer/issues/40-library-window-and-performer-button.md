新文件 `MidiPerformer.App/Views/SongLibraryWindow.axaml`(+`.cs`)——**房子和家具分开**：
面板（`SongLibraryPanel`）从侧栏搬进窗口时**几乎一行没改**，因为「长什么样」和「摆在哪、多大」
本来就不在一层。改的只有根上那道 1px 右边框（`0,0,1,0` 撤成没有）——那条线
（`BorderThickness`）的意思是「我是侧栏、右边是卷帘」，搬进窗口之后右边没有邻居。

**几处要说清楚的决定：**

- **为什么是窗口不是下拉菜单。** 用户要的三样，菜单项一条都做不到：菜单宽度跟着最长那一项走、
  改不动（要「宽一点」）；菜单项是一行字（要「完整名字」+「是否修改过」两格）；菜单里点 ×
  更是没处摆。窗口能写死 560 宽、还能拉宽（`MinWidth 420`、不设 `MaxWidth`）。
- **模态（`ShowDialog`）不是顺手写的，它是这一票唯一真正的简化。** 列表里要给正开着的那首加高亮，
  而「正开着的是哪首」在主窗口那边随时会变（保存 / 改名 / 删掉都会变）。模态期间主窗口动不了
  ⇒ 这份列表**不会过期** ⇒ 主窗口那四处「推一把刷新」的调用连同 `_libraryPanel` 字段整条删掉。
  曲库窗口自己只列、只删，不存 —— 它手上那份列表活不过一次开窗。
- **两件改盘的事（打开、删除）落在 `MainWindow`**，不在窗口里。窗口手上只有一份列表，
  而「正开着的是哪一首、文件名叫什么、提示行上那句话要不要换」只有主窗口知道。
  窗口和面板都只把名字**喊上去**（`OpenRequested` / `DeleteRequested`）。
- **打开失败：话写进窗口的页脚、窗口留着。** 装上了才关窗。反过来的话，用户看到的是窗口一闪
  —— 而窗口压在头上时主窗口的提示行根本看不见。这一支和「装上」那一支的差别见
  `TryOpenLibrarySong` 的返回值（装上返回 `null`，没装上返回那句中文）。
- **删掉的正好是当前开着的那首 → 手上那份留着。** 它还在内存里、可能还有没存过的编辑；
  顺手清掉等于「删列表里一行」动到了用户正在编辑的东西。留着的代价只是跟曲库脱了钩，
  页脚那句会说清（「按「保存」可以再存回去」）。
- **`Button.menubar` 要抹两处，不是一处。** `MenuItem` 自己就是平的，而 `Button` 底下压着
  `Controls.axaml` 那条基础样式（底色 + 1px 描边）——不抹掉这两颗会比菜单高出一圈。
  而 Fluent 的悬停 / 按下底色画在模板里那个 `ContentPresenter#PART_ContentPresenter` 上，
  只设 `Button` 自己的 `Background` / `BorderThickness` 挡不住它（同一个坑见 `Button.launch`），
  所以连 `:pointerover` / `:pressed` 一起写，**并且把 `Foreground` 钉回 `TokenInk`** ——
  少这一句的话鼠标一掠过，并排那四样里就有一样换了色。
- **`x:Name` 还是 `PerformerButton`，改的是字不是名字。** 它和
  `OverlaySurfaceTests.工具栏上的演奏入口是接上的` 之间是契约：那条测试按名字找这颗按钮，
  改文案时改坏这一处，红的是它。
- **`Button.launch` 现在产品里一处都不用了**（演奏器是最后一个用户）。样式留着 ——
  它是一条正经的令牌组合，样式册的活儿就是把它们列出来 —— 但样张上的字换成了一句中性的
  「打开」，不再指着一颗已经不存在的按钮。
- **名字框那一格的 `Margin` 从 14 改成 6**：外面新加的 `StackPanel` 自己给了 8px `Spacing`，
  6 + 8 = 原来那 14。这是「并排」那条决定的连带账。
- **`SongLibraryWindow` 得有一个公开无参构造**，和 `MainWindow` / `PerformerWindow` /
  `SongLibraryPanel` 一样。它同时是「这份 XAML 编译得过」的条件：没有的话 XAML 编译器给一条
  `AVLN3001`（「avares://…/SongLibraryWindow.axaml 运行时就加载不到」）。它**不建面板**
  （面板那条真构造对曲库是 `ThrowIfNull` 的），所以设计器里看到的是个空架子。

## 给下一个人的坑

**先说四个 PowerShell 的（每个都真花了一轮）：**

1. **`×`（U+00D7）不能当变量名，也不能当哈希表的裸键。** 它是乘号，词法那一关就过不去
   （`ParserError: 缺少右大括号`，报的位置还离得很远）。脚本里一律写成 `叉`。
2. **`-join ','` 写在参数位置会被当成参数名。** `断言 '...' (@(a) | ForEach-Object {...}) -join ','`
   里的 `-join` 被吃成 `断言` 的一个参数，数组改用默认的空格拼 —— 报出来是
   「读到 `ControlType.Button ControlType.Button`」。先算进变量再传。
3. **`(别窗.Count)` 会被当成一条名叫「别窗.Count」的命令**（`术语 ... 不会被识别为 cmdlet`）。
   要写 `(别窗).Count`。
4. **`$期望` / `$找` 这两个 scriptblock 是 `&` 在子作用域里跑的**：里面 `$查过 = $true`
   出了块就没了，下一轮又是 `$false`（这一票的日志里 `[查行]` 因此刷了 8 遍）。
   要跨轮次记东西就写 `$script:` 前缀。

**再说验证这一摊的：**

5. **合成点击：`SetCursorPos` + 相对 `mouse_event` 时灵时不灵。** 同一颗「歌曲库」按钮，
   第一次点开得出来、关掉之后再点就没反应（probe-40d/e/f 一路查下来），换窗口句柄就会变。
   可靠的是 `ClickAt`：`MOUSEEVENTF_MOVE|MOUSEEVENTF_ABSOLUTE` 归一化坐标，
   落点之前先在 x−24 抖一下（保证目标窗口一定收到「指针进来了」），再 down/up 隔 40ms。
   连做四轮开关窗 4/4 全成（probe-40h）。
6. **判据别放在「点过了」上，放在「点出来了吗」上**：点一下 → 轮询等后果 → 没等到再点一次。
   就算用 `ClickAt`，合成点击偶尔还是会丢。见 `点后等` / `双击后等`。
7. **UIA 元素会过时，窗口的根也会。** 抓在手里等六秒的元素，再去读位置会得到 `Empty` 矩形
   （报「无法将值 "NaN" 转换为类型 "System.Int32"」）；列表刷新之后旧的行容器会在树里赖一会儿，
   矩形也是 NaN。所以找元素要传**找法**（scriptblock）每次现算，而找行要筛掉 NaN / 零尺寸的。
8. **`TextBox` 的字在 `ValuePattern` 里，不在 `Name` 里 —— 这一条最值钱，它让一条断言空绿了一轮。**
   `TextBlock`（「N 首」「页脚」那些）的 `Name` 就是它画出来的字，`TextBox` 不是（`Name` 恒为空串）。
   §5 从前拿 `Name` 跟 `Name` 比，两边都是空串，「逐字相同」自然成立 —— 看着绿，其实一次都没验。
   现在 `主窗曲名` 读 `ValuePattern`，并且**把「读不到」写成一句看得见的怪话**（`★找不到曲名框`），
   不写成空串：空串会和「真的没名字」混成一样。
   同一类陷阱还有一条：`双击后等` 里那一节要验的正是「窗口自己关了」，
   于是「窗口没了」是**答案**不是异常 —— 得先判 null 再去找行，否则报出来的
   「不能对值为 Null 的表达式调用方法」落在 `找类型` 那一行，看着跟本节毫无关系。
9. **窗口句柄会被系统回收，`Visible/矩形/标题` 分不出「窗口还在只是没显」和「句柄已经指到别的窗口上了」。**
   probe-40j 拿 `IsWindow`（`P40::Alive`）逐秒采样才把这件事钉死：双击一份读不出来的工程之后，
   曲库窗 **12 秒里一直好端端的**（`Alive=True Visible=True 1146x991` 一个采样都没变），
   所以「§6 窗口凭空消失」是验证脚本自己把「窗口按设计关了」当成了崩溃。
   **怀疑窗口没了之前，先问 `IsWindow`。**
10. **`dotnet test` 的 `testhost` 会锁住 `MidiPerformer.dll`。** 后台跑着测试的时候再
    `dotnet build`，拿到的是 `MSB3027` / `MSB3021`（「文件被 testhost 锁定」）——
    和平时那条「App 开着的时候不能编译」是同一类事，但这次的元凶是测试进程。
11. **XAML 编出来的窗口要有一个公开无参构造**，否则编译期一条 `AVLN3001`
    （「avares://… 运行时就加载不到」）。39 号那轮的标准是 0 警告，这一票加窗口时踩到了。
12. **`verify-40.ps1` 会动用户的曲库**（往 `bin/Debug/net8.0/songs/` 里造两份临时工程），
    所以它开头先整目录备份、结尾按「名字 + 长度 + MD5」逐份比对还原，收尾还会断言
