# 19: 删除选中音符 + 空白处拖框改成纯多选

**What to build:** 选中音符后按 `Delete` 或 `Backspace` 把它们删掉；
在空白处拖框**不再「松手就删」**，改成只选中。

**几处要说清楚的决定：**

- **删除命令已经存在**（`ISongEditor.DeleteNotes`，真身、撤销装饰器、一整套测试都有）。
  这条工单**只接键**，不加命令、不动 Core。
- `Delete` 和 `Backspace` **两个都绑**。两个键目前**完全空闲**，任何键都没绑。
- 删**全部选中**（多选就整批删，一次调用 = 一格撤销）。
- 走撤销装饰器，`Ctrl+Z` 能整批还原。
- **删完选中态落到时间上最近的邻居**（优先右边，没有就左边），**不清空** ——
  连续删谱时手不用重新找位置。
- **拖框改成纯多选**：把 `PianoRollLane` 里那条「框住 → 直接发 `NotesDeleted`」的路径去掉，
  改成 `SetSelection`。**这是破坏手感的改动** —— 从前拖一下就没，现在拖一下只是选中。
- 顺带补上多选第二条路：现在多选**只有 Shift + 点**一条，拖框补上正好。
- **框选仍然不分音高**（`NotesInRange` 只按时间区间命中，纵向拖多高都一样）—— 保持现状，这次不改。
- 框选的结果要能直接接着按 `Delete` 删掉，这是这张工单和删除键的接缝，要验。
- 删完的选中集要按**值**重新认音（`NoteRef` 是下标寻址，删完下标整体前移）——
  用现有的那套按值镜像做，**不要在这条工单里优化它**：31 号工单会把那套东西整个删掉，
  在这里投资是白干。

**Blocked by:** 无（可以立刻开工）

## 哪些是测出来的、哪些只是写出来了

**改了什么**：`PianoRollLane` 去掉 `NotesDeleted` 事件，框选那一支改成
`controller.SetSelection(controller.NotesInRange(...))` + `RaiseSelectionChanged()`；
`TrackLaneView` 去掉那一声转发；窗口接过删除这件事 —— `DeleteSelection()`
（挑出选中集里最靠右的那个音的起点当锚点，删完交给 `NeighbourAfterDelete`
把选中落到时间上最近的邻居，优先右边），键盘上 `Delete` / `Backspace` 两个都绑在
`OnWindowKeyDown` 里。

**一行 Core 没动，一条测试没加** —— 工单就是这么写的：「删除命令已经存在，这条工单只接键」。
所以下面的条数一条不涨，那是**预期**，不是漏了。

**机器测过的：**

- 全套 **1570 条测试绿**，做之前之后**一条不多一条不少**。删除命令
  （`ISongEditor.DeleteNotes`：真身 + 撤销装饰器 + 测试）原本就在，这次只是把它接到键盘上。
- 唯一的编译期风险是「删了 `NotesDeleted` 之后还有没有人在听」—— `TrackLaneView` 那一处
  转发和窗口那一处订阅一起删掉了，App 编译 0 警告 0 错误。

**跑起来量过的**（`.scratch/verify-19.ps1`，8 节 **18 条断言，全过**；app 是真跑起来的）：

- **正题**：空白处横拖一道框住那个音，松手之后**那个音还在原处** —— 这是新旧两版的分水岭。
- 紧接着按 `Delete`，框住的那个音没了；框选出来的选中集能直接接着删，这条接缝走得通。
- `Delete` 和 `Backspace` **两个键都单独量过**。
- 删完读数条上「选中」那一格从 `轨 01 · G4 · 1.00 拍` 变成 `轨 01 · E4 · 1.00 拍` ——
  落在时间上最近的邻居上，没清空。
- 一次 `Ctrl+Z` 整批还原。
- 一个音都没选中时按 `Delete`，一个音都不少。
- **框选不分音高**：同一条横向区间，按在离那个音 60px（约 9 个音高行）的地方拖，结果一模一样。
- **整批删是一次调用**：框一大段（x 623..2900）一次删光，**一次 `Ctrl+Z` 全回来**。
  这一条是专门为了「一次调用 = 一格撤销」量的 —— 要是按音符逐个记账，一次撤销只会还回来一个音，
  第一个音的横杠就回不到原处。

**没验的，按风险排：**

1. **量到的多选全是「拖框框出来的」，没有一条是「Shift 点出来的」。** Shift + 点堆两个以上再删，
   这条路没单独走过。两条路最后都落到同一个 `controller.SelectedNotes`，
   `DeleteSelection` 也只认那个集合 —— 但没量过就是没量过。
2. **「右边没有就落左边」那一支没构造出来。** 量到的都是「右边有音 → 落右边」。
   要验得把某条轨**最后**一个音选中再删，这次没做。
3. **删完关窗口该不该提示存盘，没试。** 删除走编辑脊柱会置脏，但「脏了之后关窗口/切曲子」
   这条提示路径这次一眼都没看。
4. **撤销栈上限没压。** `MaxUndoSteps = 100`，一次删 100 个音算一格还是会被顶掉别的格子，没测。
