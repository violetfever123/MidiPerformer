# 29: 「音符按起点升序」这条不变量收进 Track

**What to build:** 「音符按起点升序」从「每条命令各自维护」变成「`Track` 自己保证」。

**几处要说清楚的决定：**

- 这条不变量现在在**三处**分别处理：
  1. **`MoveNotes`** 结尾：`OrderBy(n => n.StartTick)` 重排
  2. **`SetNoteSpan`** 结尾：`OrderBy(n => n.StartTick)` 重排（**同一句话写了两遍**）
  3. **`CutRange`**：**特意不重排**，并在注释里**论证为什么不必**
     （新的起点是旧起点的单调不减函数，所以顺序不可能被打乱）

  同一件事在三个地方各推理一次，其中两次是实现、一次是反证。
- **收进 `Track`**：出一个保证有序的构造入口。具体形状实现时定 —
  `WithNotesSorted()` 新增一个方法，还是让现有的 `WithNotes` 自己保证有序（二选一）。
  **倾向后者**：`WithNotes` 是唯一的音符入口，让它自己负责不变量，
  调用点就**不可能**忘记 —— 但那样 `CutRange` 也要付一次排序的代价（虽然它本来就有序）。
  这条权衡实现在工单里决定，并把理由写进注释。
- **`CutRange` 那处「不必重排」从「注释里的论证」变成「类型上的显然」** ——
  这正是这条工单的全部价值：把一个需要读注释才敢相信的东西，变成一个不用想就成立的东西。
- **排序仍然必须是稳定排序**（`OrderBy`，**不是** `List.Sort`）：
  起点相同的音保持原来的先后。这样「没越过邻居的改动」一个下标都不动，
  界面那套「改完重新算选中集」不会被无谓洗牌 —— 这条对 31 号工单之前的界面行为是**有意义的**。
- 这条**不改 `NoteRef` 的下标寻址语义** —— 那是 30 号工单的事。
  这里只动「谁负责排序」，不动「怎么认音」。

## 哪些是测出来的、哪些只是写出来了

**选的是哪一边：** 工单里给的两条路（新开 `WithNotesSorted()` / 让 `WithNotes` 自己保证），
选了**后者** —— `WithNotes` 是唯一的音符入口，让它自己负责，调用点就**不可能**忘记。
代价是本来就排好序的调用点（`CutRange`、`DeleteNotes`）也白排一次；
那笔账写在 `Track.WithNotes` 的注释里（都是用户敲一下才跑一次的编辑命令，不在热路上）。

**机器测过的（新 2 条，全套 1570 条全绿）：**

- `换音符之后音符按起点升序`：乱序（960 / 0 / 480）进 → 出 `0, 480, 960`，
  同时钉住「只排了序」—— 三个音还是那三个、内容一个都没变、一个都没丢，
  而且**传进去的那个数组一个字节都不动**（外面可能还拿着它）。
- `换音符是稳定排序同起点的音保持原来的先后`：同起点的音**给到 20 个**，不是随手凑的数 ——
  .NET 的内省排序在 16 个以下走插入排序，而插入排序**恰好是稳定的**，
  拿三两个音去测的话，换成 `List.Sort` 那条测试照样绿。20 个正好越过那条线。
  这 20 个刻意**按音高降序**给（稳定排序保的是「传进来的先后」，不是音高），
  前后再各塞一个起点不同的音（0 和 960）当哨兵 —— 不然一个干脆不排的实现也能原样通过。
- 既有两条只改了注释、**断言一行没动**：`挪到前面也一样重排，而且同起点的两个音保持原来的先后`
  （现在指向 `Track.WithNotes`）、`剪完音符数只减不增而且仍然按起点升序`
  （第二条现在量的是「分派出来的音符没有被那一扇门挪到别处去」）。

**没验的，按风险排：**

- **不变量是「一扇门保证的」，不是「类型保证的」。** `Track` 的构造器仍然收原始顺序
  （工单的取舍写在那条 `<param>` 上），`with { Notes = … }` 也照样能绕过去。
  **本次全仓 grep 过：`with { Notes` 只有一处命中，就是 `WithNotes` 自己**（验证过的），
  但没有任何测试盯着这件事 —— 下一个绕过去的人不会收到任何提示。
  要真钉死得让构造器私有 + 给一个全程序唯一的有序入口，那是比这条工单更大的动作。
- **「白排一次」的代价是估的，不是量的。** 「`OrderBy` 在已经有序的输入上本来就快」是一句推理，
  没有测过 `CutRange` 大曲子上的耗时。判断是它不在热路上（一次编辑一条命令），但没量。
