# 06: 演奏前的准备与掩护

**What to build:** 按下开始之后到第一个音发出之前的全部准备，以及演奏过程中给用户的掩护。

- **预检**：不是管理员权限不放行（否则按键会被 UIPI 挡掉）；输入法处于中文态不放行（否则按键被输入法吃掉而漏音）。两种都要给出明确的中文提示，不是静默失败。
- **盲倒计时**：3 / 5 / 10 秒可选。倒计时结束才发第一个音，用户用这段时间切到游戏窗口。
- **悬浮层**：始终置顶、背景透明、点击穿透（`WS_EX_TRANSPARENT`）、**绝不抢走游戏窗口焦点**。三态——倒计时 / 演奏中 / 已停止。
- **状态行**：显示当前在发哪个音，用户能对一下有没有错。
- **基准八度**：手动指定或自动选择（自动 = 让可演奏区容纳最多音符，同分时取平均八度最近的）。
- **时序档位**：稳健（30fps）/ 标准（60fps）/ 极限三档可选。
- **入口**：编辑器工具栏上的「启动演奏」按钮打开窗口二。工具栏由 07 立起来，本切片负责把这个按钮接上——它是进演奏流程的唯一入口，不能只靠 04 那个独立窗口。

这条链整体是**用例**，不是 Controller：`Core/UseCases/Perform/StartPerformance`（编排：预检 → 倒计时 → 起跑 → 挂看门狗）和 `Perform/Preflight/PerformancePreflight`（预检本身，返回 `PerformanceStartOutcome` 的那个原因）。倒计时和悬浮层三态属于同一段编排，跟着 `StartPerformance` 走。

悬浮层「不抢焦点」这条尤其关键：抢了焦点按键就发到错的地方。
