# 23: 工具栏菜单化（文件 / 操作两组）+ Ctrl+S

**What to build:** 顶部工具栏的一排按钮收进「文件」和「操作」两个下拉菜单，工具栏不再一行排开。

**几处要说清楚的决定：**

- **文件** = `导入 MIDI…` / `保存` / `另存为…` / `导出`。导入排第一 —— 它本来就是打开这个程序
  第一件要做的事，菜单第一项是对的。
- **操作** = `撤销` / `重做`。以后新增的编辑类动作往这儿加。
- **快捷键写在菜单项右侧**（`撤销  Ctrl+Z`），**不是 ToolTip** —— 菜单的标准做法，
  鼠标不用停下来等 ToolTip 就能看见。
- **`演奏器…` 留在右上角独立按钮**，不进菜单。理由：它是「去另一个窗口」，不是文件操作，
  塞进「操作」反而不好找；而且它是常驻入口，不该多点一次。
- **`歌曲名` 输入框留在工具栏原位不动**（它本来就和速度框同款，直接可编辑）。
- **新增 `Ctrl+S` = 保存**。菜单化之后按钮藏起来了，不给快捷键说不过去。
- 原本靠 `Margin` 分隔的平铺布局换成两个菜单按钮。
- **代价说清楚**：`导入 MIDI…` 现在是一个 `primary` 样式的按钮，进了菜单之后
  **它的 `primary` 视觉重量会丢** —— 菜单项没有「推荐」这个概念。这是有意接受的代价，
  因为导入是启动即用的动作，工具栏上没有它也不会让人找不到（空状态文案会指向「文件」菜单，
  见 25 号工单）。
- 按钮的 ToolTip 随之失效（`Ctrl+Z` / `Ctrl+Y 或 Ctrl+Shift+Z` 那两条）——
  归 26 号工单统一收口，**这条不删它们**（删了这条工单就不完整了，但重复说也比漏说要好）。

**Blocked by:** 无（可以立刻开工）

**Status:** done

- [x] 工具栏上只剩「文件 ▾」「操作 ▾」两个菜单按钮 + `歌曲名` 输入框 + 右上角 `演奏器…`
- [x] 「文件」里四项都能用，「操作」里两项都能用
- [x] 快捷键显示在菜单项右侧（撤销 `Ctrl+Z`、重做 `Ctrl+Y`）
- [x] `Ctrl+S` 能保存，和点菜单里的「保存」等价
- [x] 没有当前曲子时，保存 / 另存为 / 导出 照旧禁用
- [x] 撤销 / 重做不可用时，对应菜单项置灰、点了没反应
- [x] `演奏器…` 点击照旧打开演奏器窗口

### `.mproj` 那一茬：空按一次保存会把文件重写一遍，但那是格式代际、不是 bug

磁盘上那份 `Carulli_Duetto_No2_Op4.mproj` 是 **340831 字节**；什么都没改、直接按一次 `Ctrl+S`，
它会变成 **396071 字节**，第一个不同的字节在 **69**：

```
旧：false,\n  "ImportedFrom": "C:\Users\ca
新：true,\n  "ImportedFrom": "C:\Users\cao
```

也就是这份文件是**上一代 writer** 写下的，现在的 writer 会把 `ImportedFrom` 补上。
结论：「存回去必须和原文件逐字节一样」这条断言**本身就是错的**（它红过，浪费了一轮），
它判的是文件代际，不是功能。改成验**来回自洽**：

1. 先空按一次 `Ctrl+S`，取**对照** C —— 此刻磁盘上就是「手上这份谱面」；
2. 改一处（点轨头 `+1`）再存 → D，断言 `D ≠ C`（`Ctrl+S` 真的把改动写进去了）；
3. 撤销再存 → 断言**精确回到 C**（存的确实是手上这份谱面，不是别的什么）。

实测哈希三步是 `AC234BD96BF5 → 0A667C828B91 → 8BD20EC58921 → 0A667C828B91`，全对上。
脚本**无条件**把原文件还原（`finally`），并断言还原后哈希 == 原哈希
（过了：`AC234BD96BF5…`）。另外每次操作后都查了「有没有多出别的窗口」= 0，即保存全程没弹对话框。

### 没验的，按风险排

1. **「焦点在曲名输入框里时按 `Ctrl+S` 也能保存」没做、也没验。**
   `OnWindowKeyDown` 是**整段**对 `TextBox` 让开的（理由：输入框里的 `Ctrl+Z` 归它自己的撤销）。
   保存键没有那个冲突，按 Windows 惯例也该照样保存 —— 但那要让开的那一句再分一套例外出来，
   这一票明确不做，工单里就是这么记的。风险低（只是少一条便利），但它是**已知的缺口**，不是漏测。
2. **菜单的键盘导航（`Alt+F` 之类）没验。** 这次只验了鼠标点开菜单 + `Ctrl` 快捷键两条路。
   Avalonia 的 `Menu` 自带这套，但「自带」是推断，不是量过的。
3. **`导入 MIDI…` / `另存为…` / `导出` 只验了「可用」（`IsEnabled`），没验点下去真的弹文件对话框。**
   它们原来就在工具栏上、背后是同一批 `Click` 处理函数，这次只换了入口，所以风险不高 ——
   但严格说这三条是「照旧」而不是「验过照旧」。

## 给下一个人的五个坑

**1. `GetForegroundWindow() == app` **不等于**「点击会进 app」。这条最深，一整串假红都是它。**
实机量到的原话：

```
前台：[21128] Avalonia-… / 'MIDI 演奏器'                      ← 前台**就是** app
476,500 上是：[6100] Chrome_RenderWidgetHostHWND / 'Chrome Legacy Window'
窗口正中 1585,1210 上是：[6100] 同上
```

两个窗口**都不是** `WS_EX_TOPMOST`（`GWL_EXSTYLE` 量过：app `0x00240100`、那个 `0x00000020`），
纯粹是 VS Code 的主窗在 z 序上压着 app —— 顺着 app 的 `GW_HWNDPREV` 往上数，
第 4 个就是 `'● 需要的功能.txt - midiplayer - Visual Studio Code'`。
**前台只是键盘的去处；鼠标走的是「光标底下那个窗口」。** 所以 `mouse_event` 把点击交给了
VS Code，VS Code 随即拿到前台，Avalonia 一失活就把弹出层收掉 —— 菜单「弹一下就没了」，
前台还跟着换成 VS Code，于是每一条断言都红得像功能全坏了。

修法是两道，缺一不可：

- `Take()` 里**无条件**把窗口抬到非 topmost 层最上面（`SetWindowPos` `HWND_TOPMOST` 再
  `HWND_NOTOPMOST`，配 `SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE`）。**不能留着 `TOPMOST`** ——
  app 自己的弹出菜单是另一个顶层窗，主窗 long 在 topmost 层有把它压住的风险，所以落回
  `NOTOPMOST`。实测两个窗口都不是 topmost，所以这一抬就够了，不需要真 topmost。
- 判据从「前台是不是它」改成「**点上是不是它**」：`PidAt(x,y)` 比进程号（不比句柄 ——
  菜单一弹出来，点上的就是 app 自己的弹出层、另一个句柄，死抠相等会把正常点击判成假红）。
  窗口正中一道（`要前台`），**要点的那个点**再一道（`要点上`）——「正中没被压住」不代表
  「左上角那个菜单按钮没被压住」。

**2. 那一抬原来挂在 `if (GetForegroundWindow() != h)` 的分支里，于是永远不抬。**
实测到的状态恰恰是「前台**已经**是 h、但被别人压着」—— 分支进不去，抬的动作一次都没发生过。
**「已经是前台」不是「不用抬」的理由**，这两件事没关系。

**3. Avalonia 的顶级 `MenuItem` 既没有 `ExpandCollapsePattern` 也没有 `InvokePattern`**
（探针量过，都是「不支持的模式」）；**弹出层里那些条目有时有 `Invoke`、有时没有** ——
同一份脚本不同轮次里都出现过（`run23-i.txt` 里 `撤销`/`重做` 那一轮就没有，退回真鼠标才成）。
所以 `点条目` 必须**优先 Invoke、退回真鼠标**，不能只留一条。弹出层的生死只取决于
「窗口失活」，所以从「弹出层出现」到「按下鼠标」中间**不能塞任何长等待** ——
`展开` 是点完立刻每 100 毫秒轮询一次（最多 12 次），不是睡一觉再读。

**4. `@"..."@` 会插值 `$`。** C# 里只要出现 `$(`（比如字符串拼接写成 `"$(" + r.L`），
PowerShell 就把它当**子表达式**解析；报出来的是**文件末尾**「缺少右括号」、
而且 `Extent.Text` 是**空的** —— 顺着行号往回找永远找不到（我在这上面耗了好几轮）。
**C# 块一律用不插值的 `@'...'@`。** 判据：报错行号 = 最后一行且 extent 为空 ⇒ 去找没配对的
引号/括号，别信那个行号。

**5. `[void](函数)` 会把失败吞掉；函数写进管道的东西**就是它的返回值**。**
22 号记过一次 `[void]` 那个（`[void][V23]::Take($h)` 吞掉了「抢前台失败」），这次换个花样又踩：
`展开` 里 6 条失败诊断被当成「6 个菜单项」返回出去，打印出六行空白 + 「读得出四条（6 条）」。
**诊断一律 `Write-Host`**，别写进管道。

（还有两条轻的：`Sort-Object` 对中文有自己的一套排序，`操作` 排在 `文件` 前面 ——
比较菜单顺序要用集合包含，别 `-join` 比字符串；Avalonia 的 `ScrollBar` 模板里有个
`PART_LineUpButton`，Name 是 `'Line up'`，就蹲在窗口右上角，naive 的「上半带」扫描会把它
算成工具栏上的东西 —— 扫描带要锚在「文件」自己那一行的上下 ±6。）
