# 14: 编辑不再拆掉轨道视图（「编辑一下音轨就消失」）

**What to build:** 修掉「随便做一个编辑操作，音轨就消失」。编辑**成功**了，但屏幕上那几条卷帘整片空白，
要等一次改窗宽、一帧播放、一次点导航才回来。

**根因是两件事叠在一起**，都得修：

1. `MainWindow.RebuildLanes` 无条件 `LanesHost.Children.Clear()` + 全部新建。
   `Children.Clear()` 那一瞬间内容高度掉到 0，`ScrollViewer` 顺手把滚动位置夹回顶部 ——
   **每编辑一下就被弹回第 1 小节**；新控件的卷帘当帧量不出宽度（`Roll.Bounds.Width == 0`），
   `TrackLaneView.Refresh` 照 wireframe 的 `if (w < 40) return;` 直接返回，场景没算出来，
   `PianoRollLane.Render` 拿不到 `_scene` 就**什么都不画**（连轨道底色都不画）。
2. 补上那一帧要等 `LanesHost.SizeChanged` —— 而**轨数不变时那一趟根本不会来**
   （`LanesHost` 是竖着堆的 `StackPanel`，轨数不变、轨高不变，尺寸就没变）。
   移调会改轨高，所以那条路偶尔碰巧能自己恢复，看着像「有时好有时坏」。

**改法：**

- 轨数没变就**就地重挂**（`TrackLaneView.Rebind`），不重建控件树。控制器照旧每次换新的
  （它是按曲子建的一次性对象），但控件是那些控件 —— 滚动位置、焦点、改名框、删轨那一问全都在。
- 卷帘自己挂 `SizeChanged` → 重算一屏。布局一落定就补上那一帧，不指望外面谁记得来喊。
  轨数变了那一路仍然要重建，靠的就是这一条兜住。

## 哪些是测出来的、哪些只是写出来了

**这个切片一条机器测试都没有，而且很难有** —— 它坏在「控件什么尺寸、什么时候布局」
这件事上，要起窗口、跑布局才看得见。清单上那些叉全是**读代码 + 建造**得到的，没有一条是断言出来的。

具体说清楚哪几条没被验：

- 「编辑之后当帧画得出来」—— 依赖 `Roll.SizeChanged` 在进可视树布局之后真的会发。
  这是 Avalonia `Layoutable` 的既有行为，但**本切片没有一条测试钉住它**。
- 「滚动位置不被弹回顶部」—— 依赖「不 `Clear()` 就不夹 offset」。同理，没测。
- 重挂时收掉改名框/删轨确认 —— `SetConfirmingDelete(false)` 与 `CancelRename()` 都是既有方法，
  接上去是直读的；但「重挂之后焦点落在哪儿」没验。

**唯一机器验过的是编译**（0 警告 0 错误）。这个切片的正确性最终只能靠手点一次：
导入一首多轨 MIDI、滚动到中段、按一下移调 / 挪一个音，看画面是不是**原地**变、不跳回顶部。
