# 18: Ctrl+←/→ 只在焦点轨里走 + 点音符焦点跟随

**What to build:** 按 `Ctrl+←/→` 在**当前正在弄的那条轨**里前后跳音符，不再跳到别的轨上去；
点某条轨上的音符之后，焦点（轨头左边那条 3px 竖线）也跟过去。

**几处要说清楚的决定：**

- **顺序是「时间优先」。** 按起点 tick 升序排，**同一个 tick 上有多个音时按音高降序**（卷帘上高音在上，
  于是读起来就是「先上到下、再左到右」）。现在是全轨 `tick → 轨号 → 音高`，把**「轨号」那一级换成
  「限定在焦点轨」**。注意音高这一级从现在的**升序改成降序** —— 现在是从下往上走，改完才是从上往下。
- **「同一条轨」= 焦点轨**（`FocusedTrack`，`Ctrl+↑↓` 换的那条），**不是**「含当前选中音符的轨」。
  两者可以不一致：`Ctrl+↑↓` 换轨**不动选中集**（这条有测试锁住），所以会出现焦点在轨 1、
  选中的音在轨 3。
- **那个分裂情况下，`Ctrl+←/→` 从焦点轨的第一个音重新起算**（不是从视图左边缘最近的音）——
  简单、可预测，而且按 `Ctrl+←` 自然回到头。
- **到末尾停住，不绕回**（现有行为，保留）。绕回容易让人迷路。
- **视图跟随滚动**（现有行为，保留）：横向滚到该音所在小节、纵向 `Reveal()` 展开并滚进视野。
- **点音符 → 焦点跟随。** Body 命中 / Shift 加选 / 拖头尾 / 点该轨空白或拖框，**都**让焦点挪到那条轨。
- **悬浮绝对不动焦点。** 这是硬要求：否则鼠标横扫过几条轨，焦点轨、缩略图、以及轨背景的
  `LaneFocus` 高亮会一起闪。
- `Ctrl+↑/↓` 保持原样（它本来就是显式的换轨手势）。
- **副作用是有意为之**：点音符会让焦点条和该轨的浅蓝背景跳过去。这是「我在弄这条轨」该有的样子。
  如果你其实习惯「焦点钉在一条轨上不动、只是去别的轨点一下看看」，那这条要退回去重谈 ——
  改成缩略图跟「含选中音符的轨」、没选中时才退回焦点轨。

**Blocked by:** 无（可以立刻开工）

**Status:** done

- [x] `Ctrl+←/→` 只在焦点轨里走，绝不跳到别的轨
- [x] 同一个 tick 上有多个音时，顺序是音高**从上到下**
- [x] 走到两端停住，不绕回
- [x] 跳过去的音会滚进视野（横向到它所在小节、纵向展开并可见）
- [x] 焦点在轨 1、选中的音在轨 3 时，按 `Ctrl+→` 从**轨 1 的第一个音**起算
- [x] 点音符体 / Shift 加选 / 拖头尾 / 点该轨空白，焦点都跟过去
- [x] 鼠标悬浮扫过几条轨，焦点轨一个字节都不动
- [x] `Ctrl+↑/↓` 换轨的行为不变（不动选中集、不动视图）

## 哪些是测出来的、哪些只是写出来了

**机器测过的（全套 1568 条全绿，编译 0 警告）：**

这一版动了 `PianoRollControllerTests` 里的 5 条，其余全绿：

- `方向键按时间在所有轨的音符之间走` → **改成 `方向键只在焦点轨里走`**。原来那条断言的就是
  这回要去掉的行为（第 2 条轨的音更早，第一步就跳过去），所以是改写不是新增。
- `同刻的音从上往下走`：同一起点上给三个音，**数组故意按音高升序塞**，好让「照数组顺序走」
  那版和这一版分得开。往返两个方向都量了（去程 67→64→60，回程 60→64）。
- `焦点轨和选中集分家时从这条轨的开头重新起算`：先 `SelectOnly` 轨 2 再 `SetFocusedTrack(0)`，
  两个方向都得落回轨 1 的头 —— 也就是「按 `Ctrl+←` 自然回到头」那句话。
- `焦点轨一个音都没有时定位不崩`：空轨照样能聚焦（展开、改名、删除都长在轨道头上）。
  这时 `MoveSelection` 两个方向都返回 `null`、也不动选中集，尤其确认它**没有溜到别的轨上**。
- `聚焦挪没挪看得出来`：`SetFocusedTrack` 从 `void` 改成返回 `bool` 的那条约定 ——
  本来就在这条轨上、已经挪过来了、越界夹回最后一条，三种情况都得是 `false`。
  这个返回值就是 `FocusChanged` 那个事件的闸门：不这么量的话，「点一下同一条轨」
  和「点一下换条轨」在单测里长得一模一样。

既有的 `换聚焦不动选中集也不动视图`、`选中的音会滚进视野`、`走到头不绕回去`、
`设聚焦时越界夹住不抛` 一行没改，仍旧全绿 —— 第 8 条验收（`Ctrl+↑/↓` 行为不变）靠的是它们。

**跑起来量过的**（`.scratch/verify-18.ps1`，11 项全过；合成键鼠 + UI Automation 读数条）：

判据走**读数条上「选中」那一格**（格式 `轨 03 · B5 · 0.25 拍`），不靠像素 ——
这一格的轨号就是「刚才那个音落在哪条轨上」，而这条工单改的正是「下一个音去哪条轨找」。
验的关键是**让焦点和选中集分家待在两条轨上**，再看 `Ctrl+→` 往哪边倒：

- **点音符 → 焦点跟过去**：`Ctrl+↑` 六下把焦点顶到轨 01，再点轨 03 的音符，紧接着 `Ctrl+→`
  —— 落在轨 03，说明焦点确实跟着点击走了（没跟的话这一下会落轨 01）。
- **导航跟的是焦点轨**：把焦点推回轨 01 而选中集留在轨 03，`Ctrl+→` 落轨 01；
  再 `Ctrl+↓` 两下换到轨 03，同样落回它自己。
- **一步都不跨轨**：在轨 03 上连按 6 次 `Ctrl+→`、8 次 `Ctrl+←`，逐次读轨号，跑偏 0 次。
- **悬浮不许挪焦点**：鼠标在轨 01 的音符上划四个点（悬浮读数确实会跟着变），
  随后 `Ctrl+→` 仍在轨 03 —— 焦点没被划走。
- **点该轨空白也挪焦点**：`find-note.ps1 -Blank` 找一处不是音符的地方点下去，
  `Ctrl+→` 落轨 01。这条和「点音符」走的是同一句 `SetFocusedTrack`（摆在指针捕获之后、
  `switch (hit)` 之前），但值得单独走一遍 —— 哪天有人把那句话挪进「命中了音符」那个分支里，
  只有这条会响。
- **Shift 加选也挪焦点**：焦点换到轨 02，Shift 点轨 01 的音符，`Ctrl+→` 落轨 01。

**没验的，按风险排：**

- **「拖头尾也挪焦点」这一支没有被驱动过。** 四支命中里，点音符体、点空白、Shift 加选
  都在上面走过了，只有拖头/拖尾（改音符长度）没量 —— 脚本里没有拖拽。
  代码上它和那三支共用同一句话（`PianoRollLane.OnPointerPressed` 里，
  `SetFocusedTrack` 摆在捕获之后、`switch (hit)` 之前，是无条件的一句），
  所以这是「读代码读出来的」，不是量出来的。
- **「Shift 加选」这条只验了它挪焦点，没验它真的加进了选中集。** 第 11 项断言的是
  随后 `Ctrl+→` 落在轨 01；如果哪天 Shift 点变成了「替换选中」，这条照样过。
  加选本身是 09 的行为，这版没碰，但也没在真窗口里复量一遍。
- **焦点条那根 3px 竖线、轨道头的浅蓝底、卷帘的 `LaneFocus` 有没有真的重画，没看过像素。**
  脚本从头到尾只读控件文本，`FocusedTrack` 的状态是确凿的，
  但「点完音符眼睛能看见焦点条跳过去」是推出来的 —— 靠的是 `RefreshView()` 会被调，
  不是看到它画出来了。
- **纵向的 `Reveal()`（跳到折叠轨上要展开并滚进视野）没量。** 横向滚到该音所在小节
  有单测钉着（`选中的音会滚进视野` 断 `ViewStartBar`），纵向那段是 15 的既有行为、
  这版一行没动，也就没在真窗口里复验。
- **「点音符会挪焦点」是不是顺手，没问过。** 这条是工单里自己标出来的有意副作用
  （焦点条和浅蓝底会跟着点击跳）。如果你其实想要「焦点钉住不动、只是去别的轨点一下看看」，
  那要退回去重谈 —— 改成缩略图跟「含选中音符的轨」，没选中时才退回焦点轨。

**一条踩出来的坑，留给下一个写 UI 验证的人**（已经写进 `verify-18.ps1` 抬头的注释）：
点是能点空了却看着像「逻辑没生效」的。合成点击要求目标窗口**当前就在前台**，
否则那一下只剩「激活窗口」的作用；而 `WindowFromPoint` 照样说这个像素归 app
（窗口铺满整屏，盖没盖住它都归它）。找音符那几步会起子进程（`pwsh` 跑 `find-note.ps1`），
它偶尔把前台抢走 —— 于是同一份脚本时过时不过。解法是**每次点之前重新拽一次前台**
（`verify-18.ps1` 里的 `点`）。同理，**每一步用到的坐标都要现取**：
换焦点会把它那条轨滚进视野，第 1 步记下的坐标过几步就不是那条轨的卷帘了，
点歪了同样看着像「这段逻辑没生效」。
