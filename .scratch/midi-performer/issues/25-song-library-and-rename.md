# 25: 曲库与改名（内联改名、悬浮看全名、空状态文案）

**What to build:** 改曲名和改轨名都不再需要单独的按钮，直接点名字就能改；
鼠标停在曲库某一行上能看到完整曲名。

**几处要说清楚的决定：**

- 三处改名的现状各不相同：
  1. **曲库行**：一个 `改名` 按钮 + 弹窗
  2. **轨头**：一个 `改名` 按钮 + 一个点了才出现的隐藏 `NameBox`
  3. **工具栏 `SongNameBox`**：**本来就是**可直接编辑的方框，和速度框同款。**③ 不动**——
     它已经是想要的样子，是这次改造的样板。
- **轨头**：`NameBox` **常驻显示**（不再藏在按钮后面），**删掉 `RenameButton`**。
  回车确定 / Esc 取消的现成逻辑保留。
- **曲库行**：**点名字那一小块就进编辑**（名字区域本身变成输入框）。
  **这里有个冲突要说清楚**：列表行现在是**单击选中、双击打开歌曲**，所以「双击进编辑」
  会和「双击打开」直接打架。**所以用单击名字**，而不是双击。
- 行的其余部分照旧负责**选中 / 双击打开**；`F2` 改名**保留**（键盘路径不能因为改了鼠标路径就没了）。
- 改名后行的列从 `名字 / 元信息 / 改名 / ×` 变成 `名字 / 元信息 / ×`，名字那一栏自然能宽一点。
- **悬浮显示完整曲名**：给名字那个 `TextBlock` 加 ToolTip —— 它现在有 `TextTrimming`（长名字会出省略号）
  但**没有 ToolTip**，所以被截断的名字目前**根本看不到全的**。
- ToolTip 里**只放完整曲名**，**不带**「改过 / 没动过」那类元信息。理由：悬停是为了读全名字，
  掺进元信息反而让人分不清哪个是名字。
- **删掉曲库脚注**「导入的曲子存进这个文件夹，改名就是改文件名」**整条删除**。
  （实际文案用的是「文件夹」不是「文件」。）
  后半句在**改名内联化之后就依然是错的** —— 现在改名不再只等于改文件名了（曲库改名写的是工程里的
  曲名），留着就是错的，更要删。
- **两处空状态文案改短**，而且**不能再靠位置描述指向按钮** ——「导入 MIDI…」要进「文件」菜单
  （23 号工单），所以现在这两句话里的「点左上角「导入 MIDI…」」「点上面的「导入 MIDI…」」
  **全都指错地方**。改成：
  - 主窗口卷帘区 → `还没有曲子 —— 把 .mid 拖进这个窗口，或从「文件」菜单导入。`
  - 曲库面板 → `还没有曲子`
  两句话**不提位置**，只说做什么（拖进来 / 去「文件」菜单），菜单再怎么挪都不会过期。

**Blocked by:** 无（可以立刻开工）

## 哪些是测出来的、哪些只是写出来了

**机器测过的**

**一条都没有。** 这一票改的全是 `MidiPerformer.App/Views` 下的 `.axaml` / `.axaml.cs`（`git show --stat 49b9368`：6 个文件，+343/−81），没有一行进 `MidiPerformer.Tests`。
理由是这一票要验的东西全在「点下去会发生什么」这一层：哪一格能点、点了顶上来的框是谁、回车走哪条路、盘上的文件名变没变 —— 这些在单元测试里只能写成「断言 XAML 里有某个属性」，那和「真的能改名」是两件事。
代价写在「没验的」里：**`dotnet test` 这一票一次都没跑**，全仓扫描那几条（`TokenParityTests`）只是**应该**还绿。

**跑起来量过的**（`verify-25.ps1`，对着真窗口 + 真曲库目录 `bin/Debug/net8.0/songs/` 跑，**41 条断言全过，0 条红**，曲库跑完逐字节还原）

- 空状态文案、脚注、`改名` 按钮那几条（§1/§3）—— 判据是「UIA 树里那条文字在不在、逐字对不对」，不是截图。
- 悬浮看全名（§4）—— Avalonia 把 `ToolTip.Tip` 露成 UIA 的 **`HelpText`**，所以这条是**直接断言**的，不是「看着像」。
- 点名字进编辑 / Esc 取消 / `F2` / 回车提交（§5/§6）—— 鼠标那一下是真发 `mouse_event` 到坐标上（不是 UIA `Invoke`），所以「点这一格会不会进编辑」问的就是用户点的那件事。
- 改名落盘（§7/§8/§9）—— 改的是**用户自己的曲库目录**，所以脚本开工前整份备份、`finally` 里无条件还原并逐字节比对（日志最后那行「曲库已还原：cargo.mproj / Carulli_Duetto_No2_Op4.mproj（逐字节和开工前一致）」）。
- 单击/双击/点名字三条路互不抢（§10）—— 单击之后读的是 `SelectionItemPattern.IsSelected`。

**没验的，按风险排**

1. **轨头那个名字格，实机上一次都没点过。** §3 只量到「4 个名字格常驻可见、都挂着那句 `HelpText`」，也就是**要了**；「点进去改个名、回车提交、Esc 取消」这一路在 `TrackLaneView` 里走的是另一份代码（和曲库行同规矩但不同实现），没跑过。工单第一条验收项里的「回车确定、Esc 取消」目前只有曲库行那一份证据。**风险最高的一格。**
2. **悬浮提示长什么样没看过。** 量到的是 UIA 层面的 `HelpText` 等于完整曲名 —— 「鼠标停上去真的弹出来、弹在哪、深浅色下看不看得清、会不会挡住下面那一行」全归**人工**。
3. **双击落在名字那一格会怎样没验。** §10 挑的是右边那格小字（它没有 ToolTip、单击也不进编辑）。名字那一格单击就进改名了，双击的第二下会落在刚顶上来的框里 —— 界面上是什么观感没看过。工单里「单击名字」正是为了避开这个冲突，但**避开得对不对**没验。
4. **改名撞名、删除那一颗 `×`** 没碰（前者走的 `SongLibrary.Rename` 的 `InvalidDataException` 那一路，后者会弹确认框）。
5. **`dotnet test` 没跑**（见上）。下一票（27 收尾）跑全套时要把它一起带上。

## 给下一个人的坑

这一票红过四轮，最后钉死的都不是「app 有 bug」，而是**驱动本身在骗自己**。按咬人的顺序：

- **`要点上` 只看 PID 是不够的 —— 这是这一票最贵的一个坑（量了五支探针）。**
  菜单的**弹出层**、存盘/打开的那个**原生框**（类名 `#32770`）都是 **app 自己的顶层窗**，PID 和主窗一模一样，光比 PID 的闸门全放行，点就静悄悄地打在别人的控件上。
  实测现场：第 10 节要点的 `708,737` 上，UIA 读出来是 `MenuItem「导出」`——那一击点的是导出，app 弹出「导出 MIDI」的存盘框，把曲库行整个盖住，之后单击双击全打在框里。**那四条红全是这么来的。**
  判据要问「这是不是**主窗**」（`WindowFromPoint` 出来的句柄 == `$h`）。**悬浮提示是例外**：它是 `WS_EX_TRANSPARENT`，压在上面时 `WindowFromPoint` 照样报主窗（量过），所以这条判据不会误伤它。
- **菜单是谁打开的，没钉到底。** 量到的组合是：`Take` 里那记抢前台的 **Alt** ＋ 一个**没人接的回车**。Alt 单独敲不出来（probe d：敲完 `Others` 是 0 个）；不带 Alt 的空回车也敲不出来（probe i）；两样凑一起才出来（probe h：`文件` 菜单开在 `429,527 296x244`）。再细的机制没查。
  好在收场的办法是通用的、和成因无关：**点/按键之前先 `清场`** —— 抢前台 → 有菜单项或浮层就 Esc → 确认点上只压着主窗，六次不成才抛。
- **非终止错误会把假绿一路带下去。** `[V25]::GetClassName($w)` 少了 `StringBuilder` 那个参数，报的是「找不到参数计数为 1 的重载」——那是**非终止**错误：脚本接着跑，`$类` 是 `$null`，「浮层」永远收不出东西，**还一路绿灯**。凡是「返回值忘了接」的地方都要怀疑一遍。
- **「跑到一半断了」会被印成「全过」。** 断言是 `Write-Host` 打的，收尾那几句在 `finally` **之后**：脚本半路抛了、`$fail` 还是 0，于是「全过」照印。实测栽过一回（断在第 5 节，照样印「全过」，上面 16 条 OK 之外什么都没验）。现在多了一格 `$跑完了`，没跑到头就印「★ 跑到一半断了：断点之后的每一条都没验过，这不是全过」。
- **`Take` 里那句 `SetFocus(h)` 会把焦点从刚点上的控件挪走。** `F2` 挂在 `ListBox` 上，抢完前台再发 F2 就没人接了 —— §6 就这么从绿变红过一回。键盘那几下改成「app 已经是前台就直接发，不是才去抢」。
- **`ListBoxItem` 的 UIA 矩形比它能接点击的范围大一圈。** 贴着行上边 2px 点是**死区**（不选中、不进编辑，什么都不发生）。落点要挑行里实打实的元素 —— 这一票挑的是右边那格小字（`没动过`），既是元素、又没有 ToolTip、单击也不会进编辑。
- **那些「第一下点击什么都不做、第二下才生效」的老现象，这一票量到底了**：要么是**悬浮提示**开着（所以 `点` 里那趟「先停到空地 500ms 再过来」留着），要么是**菜单弹出层**压着（所以有了 `清场`）。两条都不是 app 的毛病。
