# 38: 「抽掉一段」改成在卷帘上直接拖

**What to build:** 「抽掉一段」原来要填两个小节号（「抽掉第 `__` 小节 到 第 `__` 小节」）。
这一票把那一对输入框**整个撤掉**，换成在卷帘上**横向拖出一段**：

- 拖出来的那一段**就是会消失的那一段**，屏幕上用一条**红带子**画出来（左右两条竖边 + 半透明红底，
  铺满标尺以下的整条轨）；
- **松手之后它留着**，用户先看着这一段、再决定按不按「抽掉」；
- 轨道头上那一行预览当场说出后果（删几个音、剪短几个、后面几个提前多少、这条轨 124 → 121 小节），
  看明白了才按「抽掉」。

用户原话（2026-09-20）：

> 1.我希望可以某种交互手段可以更精准的切割
> 原来的按小节切放弃 不要再出现填小节数字的窗口了。

同一句话里的第 2 条（「例如共十小节 减掉末尾两个小节 我希望是直接消失 而不是空着小节继续播放
如果还有其他音轨（无折叠）就继续播放」）分给了两张票：**「抽完这条轨真的短下去」**是这一票的
（`CutRange` 本来就是这个语义，这一票把它的后果**写进预览**，见下面那条 `124 → 121 小节`），
**「整曲长度按哪些轨算」**是 39 号的（`AudibleLength`）。

**这一票动的是「那一段从哪儿来、长什么样、什么时候算数」，五层各有一份自己的说法：**

| 谁 | 原来 | 现在 |
| --- | --- | --- |
| `PianoRollGeometry.SpanOf`（新） | —— | 按下点 → 指针，**两端吸到十六分格**、归一；吸完等宽 ⇒ `null` |
| `PianoRollController.SelectionSpan`（新） | —— | 本轨选中的音整体盖住的那一段（给预填用） |
| `Format.CutSummary` | 收 `firstBar / lastBar` | 收 `startTick / endTick`；另加 `BarPosition` / `SpanLength` |
| `PianoRollPresenter.RollOverlay.Cut` → `LaneScene.CutBand`（新） | —— | 红带子的像素框，和框选那根共用 `MarqueeOf` |
| `PianoRollLane.ArmCut / DisarmCut / CutRange`（新） | 卷帘不知道有这回事 | 装备期间整条卷帘**只划段** |
| `TrackLaneView.SetSplitting` / `UpdateCutSummary` | 两个 `TextBox` + 失焦夹取 | 只剩「抽掉 / 取消 + 一行预览」 |
| `MainWindow.OnWindowKeyDown` | Esc 收那一问 | **Enter 也收（= 按下去）** |

**几处要说清楚的决定：**

- **吸附的是十六分格，不是小节线。** 这就是用户要的「更精准」：落点可以不是小节头。
  吸的格子和**拖音符是同一套**（`PianoRollGeometry.GridTicks` = PPQ/4 = 120）——
  两处各用一套格的话，用户把音拖到某条线上、再想把那一段整个抽掉，
  拖出来的边界会和那条线差一点点，而差一点点就是「抽完之后对不上拍」。
- **「划段」是一个模式，不是「空白的另一种用法」。** 装备期间**按下就是划段，手落在音符上也一样** ——
  要剪的那一段是**时间**，和音高无关。这样也顺手挡掉一件事：按在音符上不会改选中集，
  于是预填的那一段（多半就是选中的那几个音）不会在手底下一闪就没了。想改音符就先 Esc / 「取消」。
- **预填的是「本轨选中的音」整体盖住的那一段**（`PianoRollController.SelectionSpan`）——
  用户点了几个音发现不对、再按「抽掉一段」，想剪的多半就是它们。一个音都没选中才退回
  **播放头所在的那一小节**，而且**只在装备的那一下读一次播放头**：之后播放头怎么走都不重划，
  跟着跑的话那一段会在手底下自己挪走。
- **红带子必须是红的，而且必须铺满整条轨。** 蓝的那根（`Marquee`）说的是「选中了、留着」，
  这一根说的是「这一段会**消失**」—— 意思正好相反，画成一个样子，按「抽掉」之前那一眼就白看了；
  两根还会**同时出现在屏幕上**（先框一批音、再按「抽掉一段」）。纵向铺满是另一回事：
  剪的是这段时间里的**所有**音，画矮了就是在撒谎（只盖住两行的带子凭什么剪掉第三行的音）。
  颜色只从令牌来（底 `StopSoft`、边 `Stop`，和播放头红线同一档），26 条令牌一条没加。
- **边画 2px，框选那根是 1px。** 红带子多半窄得多（十六分一格、一屏 4 小节下只有十几个像素），
  1px 的边在那么窄的一条上吃掉大半宽度，看着像一个实心红块而不是「从这儿到那儿」。
- **划好的那一段是持久的。** `ResetDrag` **不碰** `_cutStart / _cutEnd`（松手、作废都不碰），
  清它们的只有 `DisarmCut`。这是它和框选那根带子的根本分别。
- **松手不记撤销。** 真要动谱面的是「抽掉」那颗按钮（它读 `Roll.CutRange` 发 `CutRangeRequest`）；
  划一段只是把边界定给用户看一眼，一个撤销格子都不该记。
- **Enter 归这一问用**（`TrackLaneView.ConfirmPendingSplit` + 窗口那一层新接的一支）。
  撤掉输入框之后焦点多半不在任何框里，回车很自然地落到窗口那一层 —— 不接的话键盘用户
  划完一段还得回来找鼠标点那颗按钮。**灰着的「抽掉」也算用掉**：屏幕上正摆着一问一答，
  回车按进这一问里了，不该顺手去触发别的什么。
- **预览那一行改收 tick。** 切点现在可以停在任何一条十六分线上，从前那句写死的
  「后面 n 个提前 **{bars} 小节**」就是一句错话（明明提前了三拍）。现在整小节对齐时说
  「第 5–8 小节（共 4 小节）」（最常见的一刀，读起来最短），没对齐才改说两端各在小节内的哪儿
  （「第 3 小节第 1.25 拍 到 第 3 小节第 3 拍」），提前量走 `SpanLength`
  （「3 小节 0.25 拍」）。两种说法都只由这两个 tick 决定，不会出现「预览说 5–8、实际剪了 5–9」。
- **`Format.CutNeedNumbers` 改名 `CutNeedRange`**，话从「两个框都填上小节号」改成
  「在这条轨的卷帘上横向拖一段 —— 拖出来的那一段就是要消失的」—— 那一对框没了，
  这句话的任务只剩「说清那一段从哪儿来」。

## 哪些是测出来的、哪些只是写出来了

**测出来的**（真机、真窗口、UIA 读控件 + 合成鼠标在卷帘上划、PrintWindow 抓像素；
log 在 `.scratch/verify-38.log`）：

- **输入框真的没了** —— 数的是 `ControlType.Edit` 的**个数**（7 → 7），不是「找得到叫某某的框吗」。
  这是「不要再出现填小节数字的窗口了」这句话唯一的证人。
- **红带子** —— 按 `palette.Stop` 的长竖列扫出来的两组数字（1453 / 1736 / 283px），
  加上「带子里偏红、带子外是卷帘底色」这一对取色。卷帘是自绘控件，UIA 读不到它。
- **模式真的生效** —— 那个音的左沿 600 → 600，加上音数不变。
- **预览与结果对得上** —— 「删掉 19 个音」与轨头读数 1605 → 1586，两个数都是读出来的。
- **拖的是手底下的那一段，不是别处的边** —— 左沿/右沿各自跟着按下点与松手点（±60px 内），
  宽度不是整屏。
- **Esc / Ctrl+Z / 灰着的回车** 三条收尾分支，各量到音数与「那一问还在不在」。

**只是写出来了、没测到**：

- **吸到十六分格那件事本身**。脚本判的是「边落在按下/松手那一点 ±60px 内」，
  而一个十六分格在这台机器上约 **40px** —— 也就是说「吸附」与「不吸附」在这个判据下
  分不开。真正钉住吸附的是 `PianoRollGeometryTests`（`SpanOf` 那 5 条），不是实机。
- **「拖到一半把窗口重画一屏，红带子不丢」**。`Refresh` 的重建路径在代码里是通的
  （`Roll.CutRange` 每次现取），但脚本里没有「划着划着去改窗口大小 / 滚动」那一趟。
- **播放头在曲子外时预填的夹取**（`Math.Clamp(..., 1, BarCount)`，39 号让曲子能变短之后
  才有的情形）。这一趟 Carulli 没折叠，播放头一直在第 1 小节。
- **Enter 在真键盘上**：脚本走的是 `e.Key == Key.Enter` 那一支，
  但按的是合成键（`keybd_event`），不是人手。
- **划得极窄的那一段**（一两个十六分格）看着什么样。§3 划的是 300px（约 7 格）。

## 给下一个人的坑

1. **`RollOverlay.Cut` 是第 6 个可选参数，忘了传编译得过。**
   `TrackLaneView.Refresh` 里那句 `new RollOverlay(playheadTick, playheadVisible, _selectedHere,
   Roll.DragPreview, Roll.Marquee, Roll.CutRange)` —— 漏掉最后那个实参，编译器一声不吭，
   `CutBand` 就永远是 null，屏幕上**一条红带子都没有**，而别的（预览那一行、命令）全对。
   这一个坑我在这张票里踩过：`Cut = null` 的默认值让「带子没画出来」看起来像绘制的问题。
2. **tick 0 落在卷帘的最左沿上，那里被焦点轨那条 6px 蓝条（`#74ABDD`）盖着。**
   预填第 1 小节时，红带子的**左沿根本不在屏幕上**（实测那一行的同色段是
   `x 437..442 #74ABDD` 接着 `x 443..598 #2D2328`）。所以 §2 的判据是
   「**恰好**多出一条新边（右沿）」+ 「带子里偏红、外面是卷帘底色」，
   不是「多出两条边」—— 后者会假红，而且是那种让人去查绘制的假红。
3. **装备上「抽掉一段」会让轨道头长出第二行，整条卷帘往下挪。**
   `find-note.ps1` 是按**装备之前**那把尺子（轨头 Y + 60）扫的，装备之后扫到的是
   **另一个音高行**，量出来的东西全不对（我这儿量到的是「音被拖走了 300px」这种假象）。
   `find-note.ps1` 因此加了 `-Drop <px>`；§3 的做法是**量那一次拖动用 -Drop、
   量「音没被拖走」用装备之前那把尺子（Esc 之后版式回到原样）**。
4. **灰着的「抽掉」按回车：那一问**不**收掉。** 这是有意的（`ConfirmCut` 在
   `!CutYesButton.IsEnabled` 时提前返回），语义是「回车归这一问用，但这一问什么也没答应」。
   我第一版把这条断言写成「收掉了」，红了 —— 红的是断言，不是程序。
5. **`ResetDrag` 不许碰 `_cutArmed` / `_cutStart` / `_cutEnd`。** 那三个不是「这一次拖动」的状态，
   是「抽掉一段」那一问的状态：松手、作废（`CancelDrag`）、窗口重画都不该把它划好的那一段抹掉。
   但 `CancelDrag` **要**额外把 `_cutEnd` 收成 `_cutStart`（捕获丢了谁也不知道用户本来要划到哪儿），
   这一支是单独写的，和 `ResetDrag` 分开。
6. **`DisarmCut` 没装备时提前返回、一声不喊。** 窗口每次编辑都会重挂控件、无条件来收一遍
   （`TrackLaneView.Rebind`），空喊一声会让窗口白重画一屏。
7. **拖动中每帧只喊 `CutRangeChanged`，不喊 `PreviewChanged`。** 两者的代价差着量级：
   前者只让一行字重算（`CutPreview.Of` 扫一遍这条轨的音），后者让整条轨重算一屏场景。
   两个都喊就是拖动中每帧白扫几百遍音符。
8. **`.scratch/verify-38.ps1` 不能假定窗口在 (0,0)。** `find-note.ps1` 是那么糊过去的，
   这一票不行：**这台机器上 `SetWindowPos` 挪不动这个窗**（实测），所以每一趟抓图都得现取
   `GetWindowRect`、按那个原点换算（脚本里的 `抓像素` / `红边`）。
   顺带一提，`Add-Type` 那段 C# 里**一个 `System.Drawing` 的类型都不能用** ——
   试过 `-ReferencedAssemblies System.Drawing.Common`，它会把默认引用整套换掉，
   于是 `List<>`、`System.Threading.Thread` 全找不到（CS0246/CS0234 一串）。
   现在的做法是把抓下来的像素 `LockBits` + `Marshal.Copy` 成一个 `byte[]` 喂进去，扫纯 byte。
9. **`dotnet test` 有一次没复现的红。** 第一次跑（`-v q`）报 `失败: 1，通过: 1683`，
   而 `-v q` 不印测试名，那个名字没抓住；随后 **7 次**重跑（含 `-v n` 与 trx logger）
   全是 `total=1684 passed=1684 failed=0`。这一票的代码路径里没有随机数、没有时间、
   没有并行（NUnit 默认按 fixture 串行）—— 记在这儿，将来再撞见同样的数先怀疑是不是它。
10. **`verify-38.ps1` 跑一趟约 4 分钟**（要起 app、载 Carulli、抓十来次图、每次「点/拖」
    都先清场）。红了先看是哪一节：§0/§1 红 = 起窗或载曲出了问题；
    §3 红先看紧邻那句「划出来之后红带子是两条边」——它红了，后面那几条量的都是别的东西。
