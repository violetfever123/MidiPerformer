# 21: 读数栏合并 + 位置读数搬迁 + 删时长 + 删「没有循环」

**What to build:** 底部读数栏里「悬停」和「选中」两套读数合成一套；
运输条上的位置读数搬到「跳到」左边、原来的视图范围文字让位；删掉「时长」；删掉「没有循环」四个字。

**几处要说清楚的决定：**

- 读数栏现在是 **6 栏**：`悬停`(音高) / `小节` / `拍位` / `时值` / `选中`(=`轨 01 · C4（1）· 1.00 拍`) /
  右边快捷键提示。
- **合并成一套**：`轨 / 音高 / 小节 / 拍位 / 时值`。值来源是**悬浮的音优先，没悬浮就用主选中的音**
  （主选中 = 选中集里最后加进去的那个）。
- **轨号要留下。** 合并之后它是「这个音在哪条轨」的唯一线索。
- 两者都没有时，**标签和值一起隐藏**，只留右边的快捷键提示；但**保留这一条的高度**
  （那个 `MinHeight` 不动），否则鼠标一移开整窗会跳一下。
- **合并带来的行为变化**：悬浮时显示悬浮的音，鼠标一移开**回落到当前选中的音**（不是变空）。
  这是「合并」的直接兑现，不是副作用。
- **位置读数搬到导航条上视图范围文字占的那个格**（「跳到」左边）；**删掉运输条上的「位置」栏**。
- 视图范围文字（`第 1–4 小节 / 共 96`）被**取代** —— **视图范围的文字表达彻底消失**，
  只剩缩略图上的视口框。`Format.BarRange` 一并删掉（它只剩这一个调用者 + 一条测试）。
  理由：缩略图上的框已经在视觉上表达了「我在看哪一段」，文字是重复。
- 位置读数**显示播放头所在小节**（和现在一致，不改成视口起始）——
  它旁边就是「跳到某小节」的输入框，显示播放头才形成「我在哪 / 我要去哪」的对照。
- **删掉运输条上的「时长」栏**（标签和值都删）。
- 「没有循环 · 放完自动停止并松开所有按键」**只删「没有循环」四个字**，
  **保留后半句安全说明** —— 它说的是演奏结束会把手按住的键全松开、不会卡键，
  这是真有用的信息；而「没有循环」是给外人解释设计取舍的。
- **这条不改 `HintText`。** 那句话提到的东西要等 18/19/20/23/25 全部落地才写得对，归 26 号工单。

## 哪些是测出来的、哪些只是写出来了

**改了什么**（四个源文件 + 两个脚本）。

- **读数栏六栏 → 一套。** `ShowHover` / `ShowSelection` 两个方法合成 `RefreshReadout` 一个，
  多了一个 `_hovered` 字段存「此刻悬在哪个音上」，值 = `_hovered ?? _controller?.DescribeSelection()`。
  - **为什么存 `_hovered`、而不是悬停时直接把读数改写掉**：悬停是**一过性**的，鼠标一移开就得把
    选中那个音重新摆回去，于是必须回答「刚才被顶掉的是什么」—— 那正是从前那两套读数的病根
    （悬停那套变空、选中那套还留着）。存下「悬停」这件事本身、每次现算，就没有「要还原什么」这回事，
    也就没有第二份真相源。
  - 四个调用点（选中变了、跳到某小节、方向键跳选中）直接改成 `RefreshReadout()`，
    `ShowSelection` 这个名字整个没了 —— 一个入口，一条规矩。
- **位置读数**从走带条搬到导航条，占的正是视图范围文字那一格；视图范围的文字表达**彻底消失**
  （只剩缩略图上的视口框），`Format.BarRange` 和它那条断言一并删。
- **删**：走带条的「位置」栏和「时长」栏、`Format.Selection`（+它那条测试）、「没有循环」四个字。
- **`Format.Clock` 没删。** 侦察报告说它只剩 `DurationText` 一个调用者、删时长之后就是死代码 ——
  **这条是错的**：`PerformerOverlayWindow.axaml.cs:91` 还在用它拼 `TimeNow.Text`。
  差点照着错的侦察把演奏器浮窗弄挂。**教训：删「死代码」之前自己 grep 一遍，别信别人给的调用者表。**
- **一处工单没提、做的时候顺手收的**：`ReadoutDetail` 的初始可见性。XAML 默认可见，于是
  **还没载曲子**的时候读数栏是一排 `—`，而载入之后（同样没悬停没选中）是整块藏起来 ——
  同一件事两种长相。加了 `IsVisible="False"`。

**机器测过的**：`dotnet test` → **1601 通过 / 0 失败**（1602 − 1：删掉「读数条的选中格」那条测试；
`BarRange` 那一条是断言不是测试，不占数）。`dotnet build` → 0 警告 0 错误。

**跑起来量过的**（`.scratch/verify-21.ps1`，8 节 **24 条断言，全过**；app 真跑，曲子是
`Carulli_Duetto_No2_Op4`，从曲库双击打开 —— 见 `.scratch/load-song.ps1`）：

- 载入后不悬停不选中 → 读数栏上一个标签都没有（标签和值一起藏）。
- 悬停一个音 → `轨 01 / 音高 G4（5）/ 小节 1 / 拍位 2.00 拍 / 时值 1.00 拍`，五个标签齐；
  「悬停」「选中」两个旧标签都不在了；**读数条那一行和走带条的 Y，与「藏起来」那一态逐像素相同**
  （1826 / 1892，两态一模一样）—— 这就是「窗口不跳」。
- 移开、且没有选中 → 又藏回去，读数条仍在同一行。
- **点中甲（G4）→ 悬停乙（G2），读数跟着乙走；再移开 → 回到甲，不是变空。**
  这是「合并」的核心承诺，也是这张单里唯一一条**做错了不会报错、只会看着有点怪**的行为。
- 「位置」全窗只有一处，X 在「跳到」左边、和它同一行、在走带条上方；
  跳到第 7 小节后读数 `1 / 124 小节` → `7 / 124 小节`。
- 走带条上没有「位置」；全窗没有「时长」；没有「第 X–Y 小节」；「没有循环」没了、
  「放完自动停止并松开所有按键」还在。

脚本里两处值得记下来的：

- **音符的像素位置是脚本自己截图扫出来的**，不写死坐标 —— 窗口挪过、曲子换了、
  以后标尺高度改了（24 号就在改标尺）都不会让它静悄悄地指到空白处。
- **分辨音符和小节线，靠的是宽度不是亮度**：音符亮度（~85–105）和竖向小节线（~83）是**重叠**的，
  按亮度怎么取阈值都分不开；但小节线是竖的，在任何一行上只有 2px 宽，而音符是横的。
  所以阈值取低（60），真正干活的是「连续段 ≥ 24px」。—— 第一版按亮度取了 115，一条音符都没扫到。

**没验的，按风险排：**

1. **窗口很窄时这一条会不会挤**（`MinWidth=720`）。合并之后最多同时出现五组「键+值」，
   比从前左边那四栏**略宽**一点，但没在窄窗口下量过。
2. **触摸板 / 触控笔的悬停**没试 —— 只有真鼠标。悬停这条路的入口是 `PointerMoved`，
   触摸板走的是同一条，但没量过。
3. **播放中悬停**没试。读数不跟着播放头走，所以理论上和现在一样；但没构造出来看。
4. **「时长」删掉之后，改 BPM 在界面上就没有任何「总长度」的表达了**（只剩播放变快变慢）。
   这是工单明确要的取舍，但它是这张单里唯一一处**能力净减少** —— 在这儿点一下，别以后当 bug 报。
5. 走带条右边那句话现在是独立一句，前面那个「·」分隔符跟着「没有循环」一起没了。
   视觉上没影响，但和从前不是逐字相同。
