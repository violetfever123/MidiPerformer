# 36: 提示行分两层（走带 / 编辑）+ Esc 放开选中

**What to build:** 读数条右边那行快捷键提示**分成两层**，按「此刻该看哪一类」切；外加一个动作：**Esc 放开选中的音**。

用户原话（2026-09-20）：

> 知道了，不如我们采取分层提示方法：
> 第一：CTRL+Y、CTRL+Z 及"撤销"与"重做"这两个点不需要单独写，将它们作为快捷键，直接放到"操作"里面作为提示就可以了。
> 第二：(a) 未选中单个音符时：出现"播放"和"滚回上一小节播放"的提示。(b) 选中单个音符时：不再提示上述内容，转而提示移动当前音符的位置（包括左右移动、上下移动）、增强时值，以及如何选下一个音。
> 对了，将"音轨的选择"放到"播放"和"滚回上一小节播放"里面会比较好，这样就属于分类提示了。你看如何？

同一轮里补的两条：

> 1. 当你单独选中一个音的时候，按 Escape 键可以取消选择这一个音。2. 但是焦点轨不能取消选择，必须选一个。

**两层现在就是这两句**（`Format.cs` 各一份，`ReadoutHintTooltip` = 两句拼起来，中间一个 `" · "`）：

- **走带那一层**（一个音都没选中）**46 字**：
  `空格 播放/暂停 · Shift + 空格 回跳一小节并播放 · Ctrl + ↑ ↓ 换轨`
- **编辑那一层**（选中 ≥ 1 个音）**79 字**：
  `← → 移时间（一格 = 十六分）· ↑ ↓ 移音高 · Shift + ← → 改时值 · Ctrl + ← → 选同轨前/后一个音 · Delete 删除`
- **ToolTip 128 字** = 两句加起来 —— 悬停看全的那个出口还在（26 号「一句喂两处」改成了「两层拼一份全文」，第三份手抄的全文不存在，`verify-36.ps1` §0 拿 `ReadoutHintPerforming+"·"+ReadoutHintEditing` 的拼接式量它）。

**几处要说清楚的决定：**

- **分层的判据 = `SelectedNotes.Count > 0`**（问过用户：`== 1` 还是 `≥ 1`，两个选项；用户选**「选中 ≥ 1 个就切（推荐）」**）。
  所以 Shift 点出第二个音之后那一行**不换回去**（§3 钉着这一条）。
- **悬停故意不算进判据**。鼠标扫过卷帘时那一行会来回闪 —— 这是取舍，不是漏了。
- **换轨写在走带那一层，编辑那一层里不提**（用户原话：「将『音轨的选择』放到『播放』和『滚回上一小节播放』里面会比较好」；
  另问过用户「编辑那一层要不要也提一句 Ctrl + ↑ ↓ 换轨」，用户选**「不提」**）。
  理由是他自己说的：既然走带那一层已经写着换轨，看到的人会记住怎么上下切，不必在编辑那一层再说一遍。
- **撤销 / 重做从提示行和它的 ToolTip 里都撤出去了**（用户原话：「不需要单独写，将它们作为快捷键，
  直接放到『操作』里面作为提示就可以了」）。它们现在**只有一处**屏幕落点：「操作」菜单项右侧的 `InputGesture`
  （`Ctrl+Z` / `Ctrl+Y`，23 号印上去的）。这是一条**减法**，而减法最容易的翻车方式就是「顺手在 ToolTip 里补一份全文」——
  那条 ToolTip 正是「看全」的出口。
- **Esc 只放选中，绝不碰焦点轨**（用户那两条）。焦点轨必须有一个 —— 放开选中之后
  `Ctrl + ← →` 还在同一条轨上选下一个音（§5 用「轨读数还是 02」量它）。
- **Esc 排在「先关掉挂着的浮层 / 待答的问题」后面**：`OnWindowKeyDown` 的 Esc 那一支先算 `consumed`，
  只有 `!consumed` 时才 `ClearSelection()`。所以「正在回答一个对话框时按 Esc」不会顺手把选中也清了。
- **焦点在输入框里时整块让开**（从头继承的规矩，空格那一支定的）：Esc 也一样 ——
  焦点在「跳到 __ 小节」框里时按 Esc **不**放开选中（§7 量的就是这个）。这是规矩，不是 bug。
- **Esc 这条手势今天在屏幕上没有一处说得清它**（两层提示里没有它，菜单里也没有）。
  26 号的规矩是「一条快捷键要是屏幕上没有一处说得出它，就等于没有」—— 用户这一轮只要 Esc 能用，
  所以要给它一个说法的话（比如「操作」菜单里加一项「取消选中　Esc」）是**另一张工单**的事，这一票没做。
- **提示行的字只有 `Format` 一处来源**：XAML 里那个 `HintText`（`MainWindow.axaml:352`）**不带** `Text` 属性，
  窗口构造时设一次（`MainWindow.axaml.cs:161` 顺便 `ToolTip.SetTip`），此后每次 `RefreshReadout()` 里 `RefreshHint()`。
  加第二处来源最顺手的方式就是「在 XAML 里先写一句占位」，所以 `提示行的字只有Format一处来源` 专门拿三句探针盯着。
- **改键位的人会被两处挡住**，一层管一个方向：`FormatTests.快捷键提示逐字就是屏幕上那两行` 挡「有人改了这句话」，
  `ShortcutHintTests.提示里的每个手势在按键那一段里都真的绑着` 挡「有人加了键、这句话没跟上」（两张表分别对
  `OnWindowKeyDown` 的真身）；`FormatTests.提示里一条都不缺` 再挡「少一条」（少一条比多一条难发现，因为不会打错字）。
- **`花括号段` 这个测试辅助**：`ShortcutHintTests` 里几条新断言要读 `OnWindowKeyDown` / `RefreshReadout` 的**整段代码**，
  所以写了个按花括号配对切段的 helper；括号不配对时直接 `Assert.Fail`（而不是回一段短的假装没事）。

## 哪些是测出来的、哪些只是写出来了

**测出来的**（真机、真窗口、UIA 读控件 + 合成鼠标；log 在 `.scratch/verify-36.log`）：

- **两层的切换是真点出来的**：脚本按像素扫描找到第 2 条轨上的音符带（**6 条**），
  先点一个音（§2）、再 Shift 点另一个音高的（§3），每一步都重读那一行的帮助文本。
  不是调 API 设选中集 —— 那样量不到「点音会不会换层」。
- **「多选真的发生了」这条不能从读数条上看出来**：读数条只报**主选中**（`DescribeSelection` 报的是最后点进去那个），
  所以「选中集 ≥ 1」和「== 1」在屏幕上长得一模一样。§3 于是用 **Delete + Ctrl+Z 的音数见证**：
  Delete 删掉**两个**音（27 → 25）说明 Shift 点真的加进了集合，Ctrl+Z 回到 **27** 说明收尾干净
  （不给下一个人留一份改过的曲子）。
- **Esc 的四面分开量**：放开（§4）、不动焦点轨（§5）、没选中时无事（§6）、焦点在框里时让开（§7）——
  只量 §4 的话，一个「连焦点轨一起清了」的实现照样绿。
- **撤销 / 重做「撤出去」是双向量的**：提示行与它的 ToolTip 里读不到、而菜单项右侧读得到 `Ctrl+Z` / `Ctrl+Y`
  （只量前一半的话，把键位整个删掉也是绿的）。
- **代码那一侧也是量的**：`ShortcutHintTests` 里的两张绑定表逐条对 `OnWindowKeyDown` 的真身，
  §0 还把脚本里那两份预期逐字和 `Format.cs` 里的两份对了一遍（「红了先怀疑脚本抄错」）。

**只是写出来了、没测到**：

- **屏幕上到底截在哪个字**：UIA 读到的永远是全文（`TextTrimming` 只影响渲染，26 号那轮栽过）。

- **用户能不能自己发现 Esc 这一手**：见上面那条决定 —— 屏幕上没有一处说得清它，这是**知道**的开口。

## 给下一个人的坑

1. **判据在 `RefreshHint()`（`MainWindow.axaml.cs:1806`）：`SelectedNotes.Count > 0`。不要写成 `== 1`** ——
   用户 2026-09-20 明确选了「选中 ≥ 1 个就切」。写成 `== 1` 的症状是「Shift 点第二个音之后那一行跳回走带那一层」，
   而屏幕上不会有任何报错。
2. **悬停故意不算进判据**。把 hover 算进去的话，鼠标扫过卷帘时那一行会来回闪。这是取舍，不是漏了。
3. **Esc 那一支的顺序**（`MainWindow.axaml.cs:1496` 起）：先算 `consumed`（关挂着的浮层 / 待答的问题），
   `1508` 才 `if (!consumed && …SelectedNotes.Count > 0)` → `ClearSelection()`。
   谁把 `ClearSelection()` 提到前面，就会出现「正在回答一个对话框时 Esc 把选中也清了」。
4. **Esc 那一支不许碰 `FocusedTrack` / `MoveFocus`** —— 用户原话「焦点轨不能取消选择，必须选一个」。
   `ShortcutHintTests.Escape放开选中但不动焦点轨` 会红、`verify-36.ps1` §5 也会（轨读数得是 **02**）。
5. **焦点在输入框里时整块让开**（`OnWindowKeyDown` 开头那道闸门）—— 所以 Esc 在「跳到 __ 小节」框里
   **不**放开选中，这是规矩不是 bug（§7 量的就是这个）。想让 Esc 在框里也生效的话，先想清楚
   空格那一支为什么不能这么做。
6. **撤销 / 重做现在只有一处屏幕落点**：「操作」菜单项的 `InputGesture`。别再往提示行或它的 ToolTip 里加回去 ——
   那是用户要的减法，`ShortcutHintTests.撤销和重做的快捷键只在菜单项右侧说一次` 的第三半 + `verify-26.ps1` §6 都会红。
7. **提示行的字只有 `Format` 一处来源**：XAML 的 `HintText` **不带** `Text` 属性，
   构造函数里设一次、`RefreshReadout()` 里 `RefreshHint()` 再设。

8. **改提示行要动的地方现在是六处**：`Format.cs`（两份 + ToolTip 的拼接）、
   `FormatTests`（逐字那条 + 片段那条 + 「两类各归各的」）、`ShortcutHintTests`（两张表）、
   `verify-26.ps1`（`$预期走带` / `$预期编辑` / `$预期全文` + 片段数组）、`verify-36.ps1`（同三份）、
