# 12: 实机验证（等游戏装好）

**What to build:** 游戏装好之后的第一件事。整个过程没有任何自动化能替代这一步——前面所有切片都是靠对拍和假时钟验证的，只有这一步能证明「按键真的变成了游戏里的音」。

**这条不是可选的收尾，是欠着的债。** 03 和 05 里凡涉及游戏内实际效果的部分都写明了推迟到这里。

**Blocked by:** 03, 04, 05

**Status:** ready-for-agent

- [ ] 单音能吹响
- [ ] **跨八度音高正确**——按住鼠标左键 = 降一个八度、右键 = 升一个八度。这是最容易做反的地方，做反了每个跨八度的音都是错的，而且听起来只是「有点怪」，不会明显报错
- [ ] 升半音（按住鼠标中键）正确
- [ ] 最高两个音（右键 + 逗号）正确
- [ ] 三档时序（稳健 / 标准 / 极限）下都不漏音
- [ ] 悬浮层浮在游戏画面上、不抢焦点
- [ ] F6 在游戏里能急停
- [ ] 看门狗在游戏里能兜住
- [ ] 记录实测结果。**如要修时序参数或键位，先分清改的是哪一类——这两类代价完全不同：**
  - 改 `Repertoire/PlayKeys.cs`（键位表，我们自己抽出来的文件，**不在移植范围**）→ 直接改，然后重跑 01 与 02 的对拍
  - 改 `InputTiming.cs` / `NoteMapper.cs` / `Music.cs` / `EventBuilder.cs` 里任何一个 → 这是**有意偏离「逐字移植」**。它不是一次编辑，是一次决定：01 的「与原版逐行一致」断言、对拍基线、以及 `Repertoire/` 的定位要**一起重新交代并写进 spec**。只改文件不交代，01 会永久变红而没人知道为什么
