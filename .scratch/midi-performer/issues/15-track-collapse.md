# 15: 折叠一条轨（「音轨的折叠功能没做」）

**What to build:** 轨道头上那个**折叠**按钮真的能收。收起来之后这条轨只剩轨道头 + 一行
「已折叠」加一根压扁的音符条（wireframe 的 `.strip`），卷帘藏起来；再按一下（这时按钮上的字
是「展开」）原样回来。**折叠只是「先不看它」** —— 谱面、选中集、播放、导出，一个字节都不碰。

**几处要说清楚的决定：**

- **一个按钮两句话**，不是「折叠 / 展开」两个按钮：它管的是同一条轨的同一个开关，
  按内容的字面意思走（wireframe 里那句 `this.textContent = now ? "折叠" : "展开"`）。
- **状态住在控件上**（`TrackLaneView._collapsed`），不在窗口里。14 把「编辑就重建控件树」改成
  就地重挂之后，住在控件上的状态天然跟着重挂活下来 —— 收起来再挪一个音，这条轨不会自己弹开。
- **轨数真的变了**（删轨 / 撤销把它拿回来）时控件只能重建，那一格跟着丢，所以窗口在重建前
  把它抄下来、重建后按**轨的身份**放回去。身份取的是模型自己那对唯一键 `(TrackIndex, Channel)`，
  **不是下标**：删掉第 0 条之后 `Song.Tracks` 的下标整体前移，按下标带会把折叠挪到别人身上。
- **收起来也要认得出是哪条轨**：那一行底色跟着轨号奇偶走，和卷帘的 `.lane.a` / `.lane.b`
  取的是同一对令牌（Avalonia 的选择器写不出 `nth-child`，奇偶用一个 `.b` 类补）。
- **Ctrl + ←/→ 定位到一条收起来的轨上时顺手展开**（`Reveal()`）并滚进视野。不展开的话
  「跳过去了」在屏幕上一个像素的变化都没有，用户只会以为按键失灵了。

**Blocked by:** 14（折叠住在控件上，而控件能不能活过一次编辑是 14 决定的）

## 哪些是测出来的、哪些只是写出来了

**这个切片一条机器测试都没有**，和 14 一样 —— 它整个坏在「控件什么状态、什么时候布局、
可视树上谁在谁里」这件事上，要起窗口、点按钮、看布局才看得见。

**机器验过的是编译**（0 警告 0 错误）和**原有 1486 条测试没有回归**。折叠自己那条路
没有 NUnit 测试碰过。

**跑起来量过一遍**（.scratch/uia-check.ps1，走 UI Automation 量控件的真几何，不是看截图 ——
截图那条路在 200% 缩放下只抠到屏幕左上角一块，看着像窗口被切了，其实是拍歪了）：

- 收起第一条轨 → 那颗按钮的字变成「展开」，`已折叠` 那一行出现 1 处，下面各轨整体上移
  （第二条轨头从 y=780 到 y=286，494 物理像素 = 247 逻辑像素），**再按一次四条轨头的
  Y 坐标和最开始逐条相同** —— 收放是干净的，没有攒下高度。
- **折叠活过一次编辑**：收起第一条轨之后按「撤销」（撤销一次音色改动，走的是
  `ApplySong` → 换了一份 `Song`），四条轨的按钮仍然是 `展开, 折叠, 折叠, 折叠`，
  `已折叠` 仍在。这正是本切片风险最高的那一条，现在是有量的。
- **收起的那一行底色确实跟轨号奇偶走，而且和卷帘取的是同一对令牌**：在窗口里沿 x=2600
  竖着扫一列像素，把成片（≥12px）的颜色段读出来 ——
  第 1 条的卷帘 `#1D232B`（= `TokenLaneA`）、第 2 条的条 `#20272F`（= `TokenLaneB`）、
  第 3 条的条 `#1D232B`（`TokenLaneA`）、第 4 条的卷帘 `#20272F`（`TokenLaneB`）、
  第 5 条的卷帘 `#1D232B`。**奇偶对上了，收起来的那条和第 4/5 条卷帘的深浅是同一对值。**
  顺带量到：那一行 46 物理像素高（23 逻辑），里面那根压扁的条 18 物理像素（= 9 逻辑，
  和 `.strip-mini` 的 `Height=9` 对上），条本身是 `TokenNote` 0.45 不透明度叠在底色上
  （`#3C4651` = 0.45×`#5E6B7A` + 0.55×`#20272F`，逐位相同）。

还是没验的，按风险排：

- **轨数真的变了那一支**（删轨 / 撤销把轨拿回来 → 控件重建 → 折叠按 `Identity` 放回去）。
  这次触发的编辑轨数没变，走的是就地重挂那一支，**重建支一次都没跑到**。它依赖
  `Identity` 在重建前取到的是**旧的**控制器手里的轨，而 `SyncLanes` 在重建那一支的
  **开头**就把 `_controller` 换成新的了 —— 这里能对上是因为同一首曲子的新一份里
  `(TrackIndex, Channel)` 不变；值得手点一次删轨 + 撤销，看收起来的那几条是不是还收着。
- 「Ctrl + ←/→ 会展开」——依赖 `Reveal()` 里的 `this.BringIntoView()` 真的滚得动。
  `BringIntoView` 是 `ControlExtensions` 上的扩展方法，**必须带 `this.`** 才解析得到
  （光写 `BringIntoView()` 是 CS0103，扩展方法只在「表达式.名字」这个形状上找），
  这一条是编译器逼出来的；但「滚到哪、滚没滚」没有断言，也没量。
- 「收起来的那一行看得出是哪条轨」—— 底色取的是 `TokenLaneA` / `TokenLaneB`，
  上面按像素量过，和卷帘是同一对值、奇偶也对得上。
- **「只看这条」还是没做**（右边那句灰字照实写着），折叠和它互不影响，但两条一起看的时候
  那一行会比现在挤。
