# 37: 「Esc 取消选中」写进编辑那一层的提示行

**What to build:** 36 号把 Esc 这一手做出来了（放开选中的音、不动焦点轨），可**屏幕上没有一处说得清它** ——
它既不在两层提示里，也不在菜单里。26 号留下的规矩是「一条快捷键要是屏幕上没有一处说得出来，就等于没有」，
所以这一票就是给它找一处。**位置是用户定的：编辑那一层**（选中了音才显的那一行）。

用户原话（2026-09-20）：

> 取消选中放在"选中一些音符之后"的东西提示行。

来路：36 号做完之后我提了两个开口，其中一个是「Esc 这一手今天屏幕上没有一处说得清它 ——
要不要我在『操作』菜单里加一项『取消选中　Esc』？」。**用户没要菜单，要的是这一行**（这句就是答复）。

**几处要说清楚的决定：**

- **位置 = 编辑那一层的末尾。** 一层一层的理由都是现成的：
  (a) 它**只在「已经选中了音」的时候才有意义**（一个音都没选中时按 Esc 什么都不做 —— 36 号 §6 量的），
  所以它归编辑那一层，这也正是用户那句话里的「选中一些音符之后」；
  (b) 排**末尾**是因为读起来是「干完这些之后想放手就按 Esc」——
  但它因此成了**最先被省略号截掉的那一条**（下面那条「代价」写着实测）。
- **不进「操作」菜单**：我给的建议是菜单，用户改成了这一行。所以 `操作` 菜单里**没有**它，
  这一行是 Esc 这一手**唯一**的屏幕落点 —— 和 `Delete 删除` 一样（Delete 也没进菜单）。
- **文案是 `Esc 取消选中`**：跟同行的 `Delete 删除` 一个句式（键 + 动作），
  不写「按 Escape 键可以取消选择这一个音」那种句子 —— 这一行是一串手势，不是说明书。
- **37 号只动文案，一个字节的代码逻辑都没动。** Esc 那一支还是 36 号那一份
  （`MainWindow.OnWindowKeyDown` 的 `Key.Escape` 分支：先 `consumed`、再 `ClearSelection()`、绝不碰 `FocusedTrack`）——
  这一票改的是「屏幕上说不说得出来」，不是「按下去管不管用」。
- **两个方向都要钉**：编辑那一层里**有**它（§2），**走带那一层里没有**它（§0/§1）。
  只钉前者的话，把这句话挪到走带那一层（一个音都没选中时说「Esc 取消选中」）也是绿的。
- **绑定对账表多了一行**（`ShortcutHintTests.编辑那一行`）：`Key.Escape` + `ClearSelection()`。
  左边单写 `Key.Escape` 的话，把那一支改成「Esc 什么都不做」也是绿的。
- **「一处来源」又多一根探针**（`Esc 取消选中` 不许在 `MainWindow.axaml.cs` 里出现）——
  这一行是全程序反复被抄错的地方，探针是防抄的。

**代价是知道的（实测，不是估的）**：这一行是**右对齐**的，窄了会出现省略号，
而截掉的正是**末尾**那几条 —— 新加的这条排在最末尾，所以它第一个被截。
`.scratch/probe-37-hint-width.ps1` 量的三个数：

- **编辑那一层：90 字，自然宽度 1247 物理 px**；装着曲子、默认窗口下提示行的框是 **1486 物理 px**
  → **装得下**，左边还空着 **237 px**（右对齐，所以富余都在左边）。
- **走带那一层：46 字，643 px**（框 2254 时量到，载曲前后一样）。
- **框宽 ≈ 窗宽 − 848 px**（两个点：窗宽 2334 → 框 1486；窗宽 3034 → 框 2186）。
  所以编辑那一层要全文显示，窗宽得 ≥ **2095 物理 px（≈1048 逻辑 px）**。
  app 的默认窗口是 `Width=1180` 逻辑 px（2360 物理 px）—— **默认档装得下**；
  `MinWidth=720` 逻辑 px 那一档框只剩 592 px，两层都靠 ToolTip 看全（26 号的设计）。

## 哪些是测出来的、哪些只是写出来了

**测出来的**（真机、真窗口、UIA + 逐列找墨迹；log 在 `.scratch/probe-37-hint-width.log`）：

- **屏幕上那一行真的是 90 字**（UIA 读 + 逐字比对），且**没被截**：靠的是像素 ——
  墨迹 1247 px、框 1486 px、左边空 237 px。UIA 在这一条上是**不能作证**的（`TextTrimming` 只影响渲染，
  UIA 永远报全文；26 号那轮栽过一次）。
- **自然宽度是「不随框变」的那个数**：默认窗口（框 1486）和宽窗（框 2186）两次量到的墨迹都是 **1247 px** ——
  两次一样才说明它是文字自己的宽度，而不是「框有多宽就填多宽」。
- **框宽与窗宽的关系**：窗宽 2334 → 框 1486、窗宽 3034 → 框 2186，两个点差 700/700，
  所以「窗宽 − 848 = 框宽」是量出来的，不是猜的。
- **ToolTip 是 139 字**（46 + 3 + 90）：`verify-26.ps1` §1 逐字比对 + §4 悬停那张纸上读到的也是这一份。

**只是写出来了、没测到**：

- **窄窗下到底切在哪一个字**：UIA 读到的永远是全文，能作证的只有「框宽 592 px < 自然宽 1247 px」
  （26 号 §3 量的窄档）+ 右对齐 + `CharacterEllipsis` 这三样推出的「末尾那几条先没」。
  想知道确切边界只有一条路：**看 `.scratch/probe-37-hint.png`**（默认窗口那张，全文都在）
  和 `.scratch/shot26-min.png`（26 号留的窄窗那张）。
- **用户会不会真的读到末尾这一条**：发现性问题，测不了。能说的是它现在**屏幕上有**（默认窗口下看得见）。
- **`Esc` 在别的键盘布局 / 输入法下**：没量（这一票也没碰按键那一半）。

## 给下一个人的坑

1. **量提示行的墨迹，扫描带只能取提示行那个框**自己**那一段。** 它和读数栏**在同一行**上
   （26 号量过：读数栏在场时两者共用一个 Y），往左多留 40 px 就会把读数栏那几个值
   （「轨 02 音高 C4（1）…」）当成墨迹 —— 第一版就是这么量出「编辑那一层自然宽 **2252** px」的，
   虚高近一倍，看着像「加了 Esc 就装不下了」，差点让我把这条提示挪走。
2. **截断的判据是「墨宽 ≈ 框宽」，不是「右富余 ≈ 0」。** 这一行是**右对齐**的
   （`TextAlignment="Right"`），没被截的时候墨迹照样贴着框的右边缘（右富余 1~2 px）。
   第一版拿右富余当判据，两层都被判成「在出省略号」，白拉了一次宽窗。
3. **框宽 ≈ 窗宽 − 848 物理 px**（这台机器、200% 缩放下量的）。
   编辑那一层 1247 px → 要窗宽 ≥ 2095 物理 px（≈1048 逻辑 px）才全文显示。
   想再往这一行加一条的话，先算这一笔：**每加 10 来个字，门槛就往右挪约 140 物理 px**。
4. **`Esc 取消选中` 在末尾 = 它是最先被截掉的那一条。** 这是用户定的位置的**已知代价**；
   真要让它在窄窗下也看得见，只能往前挪（35 号那次就是这么办的）——
   但别忘了它和 `Delete 删除` 一样，是**唯一**能把这一手说出口的地方（菜单里没有它）。
5. **改这一行现在要动的地方是七处**：`Format.cs`、`FormatTests`（逐字 + 片段 + 层归属）、
   `ShortcutHintTests`（两张表 + 探针表）、`verify-26.ps1`（`$预期编辑` + 两处片段）、
   `verify-36.ps1`（`$预期编辑` + 片段）、`docs/wireframe.html` 那段注释、
   `MainWindow.axaml` 里提示行上面那段注释（今天从 **343 行**起，里面写着这两层的实测宽度）。少改一处的症状还是那句：
   「测试红在一句和这票无关的话上」——别改那句话，去补漏的那一处。
6. **别把 `取消选中` 加进 `verify-36.ps1` §2 那个负向循环。** §2 量的那一刻屏幕上**就是**编辑那一层
   （它当然有这三个字），在那儿断言「没有取消选中」是一条自相矛盾的断言 —— 第一版加错了地方，红了一次。
   方向上的反证在 §0/§1（一个音都没选中时**不许**露头）。
7. **`probe-37-hint-width.ps1` 的函数报告用 `Write-Host`**：那个函数是**有返回值**的（一个哈希表），
   普通字符串会被 `$x = 量提示行 …` 一起吞进变量，屏幕上什么都看不到 —— 第一版白跑了一轮
   （只有 `=== N. …` 那几行是我的、函数的报告一行没出来）。
