# 08: 编辑脊柱：改 BPM 与轨移调

**What to build:** 一条**完整的编辑竖切**——从界面到模型再回到界面。这一块的价值不在于那两个命令，而在于把整条编辑脊柱立起来：接口、装饰器、撤销栈、重做栈、UI 接线、撤销后重绘。后面的编辑命令都是往这条脊柱上挂。

- **改 BPM**：输入框显示和输入的都是**具体的 BPM 数字**（比如 `76`），不是百分比、不是倍率。实现是缩放 `TempoMap` 里的速度事件，**音符数组一个字节都不动**。卷帘上音符的位置和时值跟着一起缩放。
- **轨移调**：单位是半音，提供 `±1` 和 `±12` 两种步进。移调是 `Track` 的属性，**永远不写回 `Note`**。
- **撤销**：`Song` 不可变、命令返回新 `Song`，所以撤销栈天然就是「一摞旧的 `Song` 引用」。用 `UndoableSongEditor` **装饰器**横着罩在所有命令外面——撤销代码不切进任何一条命令内部，`SongEditor` 里一行都没有。将来加新命令，撤销自动生效。

`ISongEditor`（放 `Core/Ports/Inbound/`）值得开接口的**唯一**理由就是装饰器给了它第二个实现。

编辑命令**不收 Request、不返回 Result**——直接收散参（BPM 数字、半音数、音符号），返回新的 `Song`。`Song` 不可变，「改没改」就等于「引用是不是同一个」，装饰器用 `ReferenceEquals` 判断就行，不需要 `Changed` 字段。全程序唯一值得打包成具名 Request 的是演奏那条链（`StartPerformanceRequest`，五六个参数），跟这一块无关。

## 落了什么

- `Core/Ports/Inbound/ISongEditor.cs`（新）：全程序唯一一个入站端口。开它的唯一理由就是装饰器给了它第二个实现；
  `Undo` / `Redo` / `Reset` / `CanUndo` / `CanRedo` **故意不长在接口上**，只长在装饰器上——界面拿到的就是装饰器。
- `Core/UseCases/Editing/SongEditor.cs`（新）：命令的真身，纯函数、无状态，一行撤销代码都没有。
- `Core/UseCases/Editing/UndoableSongEditor.cs`（新）：装饰器，撤销栈 + 重做栈 + 封顶 100 步。
- `Adapters/Presenters/Format.cs`：只加了一个 `Transpose(int)`（`+3 半音` / `-12 半音` / `0 半音`），
  并**改写了 `ReadoutHint`** —— 原文写着「编辑归 09 与 08」，08 做完了就得改口，
  留着等于界面上挂一句假话。现在写的是「…Ctrl+Z 撤销 / Ctrl+Y 重做 · 编辑（拖音符 / 改时值 / 框选）归 09」。
- `Adapters/Controllers/PianoRollController.cs`：只加了 `RestoreSelection(track, note)` 一个最小方法。
  编辑之后 `TempoMap` 换了、控制器必须重建，选中得能放回去；越界就清空（那是「删轨」那类命令之后的状态）。
  类注释里「08 不碰这个文件」那句也跟着改了。
- `App/Views/MainWindow.axaml(.cs)`、`App/Views/TrackLaneView.axaml(.cs)`：走带条上的速度框（回车提交）、
  工具栏的撤销 / 重做两颗按钮（栈空时置灰）、走带条上新加的**时长**读数、轨道头上的移调步进器。

几条实现上的取舍：

- **改 BPM = 按同一个倍数缩放整张速度表**，倍数 = `60 000 000 / 新BPM / 开头那条事件`。
  音符一个字节都不动（连 `Track` 对象都是原样复用），因为音符只存 tick。
- 速度表里**没有 tick 0 事件**时，基础速度住在 `TempoMap` 的默认值（=120）里，光缩放现存事件够不着它：
  这种曲子会补一条 tick 0 事件。变速点在中间、开头是默认速度的曲子（语料里就有）全靠这条。
- **没改就还回来同一个引用**（`ReferenceEquals`）：装饰器拿它当「要不要记账」的判据，
  返回一个内容一样的新对象会让撤销栈里攒下按了没反应的格子。
- 移调在界面上算「当前值 ± n」，交给命令的永远是**绝对半音数**——「绝对赋值」这条语义只有界面一处解释。
- 撤销 / 重做的键盘入口（Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z）走窗口的 tunneling `KeyDown`，
  排在「焦点在文本框里就让给文本框」那道判断**之后**：在速度框里按 Ctrl+Z 该撤的是他刚打的字。
- 编辑会把播放停下来（`PreviewPlayback.Load` 里就 `Stop()` 了）。播放头 tick 先记下来，
  改完用**新的** `TempoMap` 换算回秒——不快照这一下，改完速度播放头会跳到别的小节去。
- 装配点：`MainWindow` 里 `new UndoableSongEditor(new SongEditor())`。`App.axaml.cs` 本切片不许碰，
  而 `MainWindow` 本来就在 `new PreviewPlayback`，先落在这儿，合并点由主协调者收。

## 三个坑

1. **（真 bug，测试逮住的）新命令没有清空重做栈。** `Record` 的文档注释写着「命令确实产出了新对象才压栈**并清空重做栈**」，
   代码只做了前半句。表现：撤一步 → 又改个别的 → 按重做，会凭空跳回那条已经被抛弃的时间线上。
   `撤销之后又改新的重做链就没了` 这条一跑就红。修法是在 `Record` 里 `PushUndo(before)` 旁边 `_redo.Clear()`。
2. **`TempoMap` 的构造器会丢掉 tick 0 上那条等于默认值（500000）的变速。**
   写测试样本时拿它当「开头 120BPM」是会翻车的：那条事件根本存不进去，
   于是「有一张两条事件的速度表」这个前提其实只有一条（`SetBpm` 到 120 会返回同一个引用倒是**对的**——结果确实没变）。
   语料里的变速曲同理，所以那条扫语料的断言比的是「原来的每一条还在不在原地、快慢是否被同一个倍数乘过」，
   **不比条数**——开头原本没有事件的曲子，改完会多出一条来。
3. **Avalonia 的 `TextBlock` 没有边框属性**（`AVLN2000: Unable to resolve ... BorderBrush on type TextBlock`）。
   移调那个「值」左右的两条竖线原本想直接画在文字上，第一次构建就红在这儿；
   改成套一层 `Border Classes="step-value"`（`BorderThickness="1,0"`）——形状和 wireframe 一样，只是多了个容器。

另外两处是设计上的，不是坑，写在这儿免得下次当 bug 查：

- **回车提交时会话的焦点还在速度框里**，得先把焦点放开（`LanesHost.Focus()`，那个 `StackPanel` 因此加了 `Focusable="True"`）
  再改数据。顺序反了的话，`RefreshView` 里那句 `if (!BpmBox.IsFocused)` 的防抖会把刚提交的数字又咽回去，
  用户看到的是「回车了，框里还是旧值」。
- **改 BPM 之后卷帘一个像素都不动**（见下一条），所以「改完到底看得见什么」的答案全压在走带条那个**时长**读数上，
  它由 `Format.Clock(song.TotalSeconds)` 给出。

## 「改 BPM 后卷帘上音符的位置和时值跟着缩放」

这条按字面**没有实现，也不该实现**，如实留空：

- 卷帘是 **tick 轴**（一屏固定 4 小节，没有缩放），音符只存 tick，小节刻度只由分辨率与拍号决定。
  改速度改的是「一个 tick 有多长」，音符相对小节的位置**本来就不该变**——那正是「音符数组一个字节都不动」的另一面。
- 跟着缩放的是**秒**那一侧：整曲时长、播放快慢、一切 tick → 秒 的换算。
  测试把两边都钉住了：`改BPM不改变卷帘上的小节刻度与音符位置`（`BarTicks` / 控制器的小节数与横向坐标都不变）
  与 `整曲秒数按新旧速度之比缩放`（慢一半则秒数翻倍）。
- 界面上能看见的只有走带条的「时长」读数变小 / 变大。**「音符在谱面上被拉开」自始至终没有发生，这是对的。**

## 未验证 / 要人眼看的

自动化测试够不着 `App/**`（没有 UI 测试基建），下面几条得真起窗口点一遍：

1. 速度框里打 `76` 回车：时长读数跟着变；打 `0` / `abc` / `1e9` 回车时报中文错、框里回到原来的值；
   打 `120` 回车等于没改，撤销按钮不该亮。
   **拿一首变速的曲子试**（语料里 22/63 首是）：播到速度不一样的那一段停下，
   框里**不该**跟着那一段变 —— 它写的始终是 tick 0 的基准速度（复查第 1 条改的就是这个）。
2. 轨道头上的 `−12 / −1 / +1 / +12`：值跟着变（绝对赋值）、卷帘一个像素都不动；连点 `+1` 十二下 = 一个八度。
3. 撤销 / 重做两颗按钮、Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z、以及**在速度框里按 Ctrl+Z**（该撤的是刚打的字，不是谱面）。
4. 改完之后选中与视图位置还在原处（重建控制器时 `RestoreSelection` / `SetViewStart` 放回去的那两下）。
5. 播放中改速度：播放停下、播放头还在原来那个 tick 上。

## 复查（对着整份 diff 又过了一遍，改在这之后）

派了一个专门挑错的复查。它把 63 首语料当探针跑，量出来的数都在下面（**不是估的**）。
查出两条真的，都改了；另外几条小账里改了三条注释和一处测试。

### 1. 速度框**显示的是播放头那一点的速度，写进去的是 tick 0 的基准速度**（真问题，已改）

`CurrentBpmText` 取的是 `BeatsPerMinuteAt(播放头)`，而 `SongEditor.SetBpm` 锚在 **tick 0**、
把整条变速表按比例缩放。两个坐标系，中间没人对账。原来的注释认了这一点，判断是
「匀速曲子上这两者是同一个数（变速曲子上才分得开）」—— 当成小事放过了。

**它不是小事：63 首语料里 22 首不止一个速度值，17 首的差异超过 20%。**
拿 `Carulli_Duetto_No2_Op4.mid`：tick 0 是 50，61920 那一段是 150。播到那一段停下，
框里写着 `150`，用户**一个字都没打**直接回车 —— `SetBpm(150)` 把 tick 0 改成 150、
整首按 3 倍缩放：**347.8 秒 → 115.9 秒**，撤销按钮亮了。用户以为那一回车是「确认一下现在的值」。

**改法**：`CurrentBpmText` 改成取 **tick 0 的基准速度** —— 一个显示的数和一个写入的数
必须是同一件事。改完顺带把「打 120 回车等于没改，撤销按钮不该亮」这条人工检查
从「只对匀速曲子成立」变成普遍成立。

### 2. 空操作时框里留着用户打的原文（真问题，已改）

`ApplySong` 遇到同一个引用会提前返回，跳过 `RefreshView` —— 于是框里打 ` 76 ` 或 `076`
再回车，算出来的值和生效的值一模一样、`SetBpm` 返回同一个引用、`RefreshView` 没跑，
框里还留着那串原文。正是这条要消掉的「回车了，框里怎么还是这个」的困惑，
只是挪到了空操作那条路上。**改法**：`OnBpmKeyDown` 提交后自己把框写成规范样子。

### 3. 改了三处注释和一处测试（小账）

- `UndoableSongEditor` 的类注释说「代价是内存（一万音符一份快照约 400KB）」—— **快照这个说法是错的，
  差三个数量级**：音符数组从来不复制，`SetBpm` 原样带走整摞 `Tracks`、`SetTranspose` 只换一条。
  一步真正留下的是「一个 `Track[]` + 一个 `Track`」或「一张 `TempoMap`（语料里最长 3043 条变速 ≈ 97KB）」。
  封顶没问题，但照着「快照」估内存会估错得离谱。
- `WinmmPreview` 和 `PianoRollGeometry` 里各有一句「归 08」—— 08 做完了，**这两件都没做**：
  每轨音色是新的独立一条，分段小节刻度是**特意不做**的（卷帘是 tick 轴，小节多宽和速度表无关）。
  留着就等于代码里挂着两句假话，和 `Format.ReadoutHint` 那次同一类。
- `Format.Transpose` 是 08 唯一新增的公开 API，一条测试都没有。补了一条
  （`移调读数只在有方向时才带符号`，含 `int.MinValue` / `int.MaxValue` 两个边上）。

### 复查说没问题的地方（它试着攻过，没攻破）

撤销/重做的状态机是干净的：新命令真的会作废重做链（那条测试是真回归测试）、
撤销到底安全空转、封顶丢的是最老的一步、`LoadSong` 会 `Reset()`、`_song` 只在两处赋值，
构造不出让栈和界面对不上的序列。模型不变量（`Song` 引用相等、`Track` 值相等、
两个命令都不往 `Note` 里写东西）、XAML 无颜色字面值、以及 `Tag="-12"`（ASCII 减号）
和 `Content="−12"`（U+2212）那个陷阱（它逐字节验过，没踩上）都是对的。

### 还留着的两条（**明知未改**）

- **`SetBpm` 在变速曲子上不是幂等的**：框里显示的是四舍五入到整数的基准速度，
  而基准速度常常不是整数（`Trainpod.mid` 是 160.911，框里写 161）。照着 161 提交会真的改掉这首曲子，
  于是「回车一下」记下了一步撤销。5/63 首更严重：连按十次同一个数会漂 1 微秒 × 十步
  （每次都对所有变速事件重做一遍 `RoundMicros`）。**没改** —— 要根治得动舍入策略
  （多半是只在值真的变了才重写，或者框里保留足够精度），那是比这条工单大的改动，
  而且会和「框里只写整数」这个已经是刻意选定的显示方式打架。**这是一个已知的坑，不是没发现。**
- **SMPTE 分辨率的曲子**：`SetBpm` 会重写速度表，但 `TempoMap.SecondsAt` 在 SMPTE 模式下
  **根本不看速度**，所以秒数一点不变 —— 一次「改了个寂寞」但记了一步撤销。
  语料里 0/63 首是 SMPTE，属于潜伏的。同上：没改，记在这儿。
