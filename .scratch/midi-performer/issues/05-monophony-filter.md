# 05: 单声部判定与演奏轨下拉

**What to build:** 游戏里的口琴同时只能响一个音，所以下拉框只列能弹的轨。

`MonophonyCheck` 的判据是**起音是否同时**（同一瞬间 ±30ms 内出现两个及以上起音 → 多声部），**不是时值是否重叠**。前音还在响、后音才起（连奏）不算多声部——用「时值重叠」当判据会把连奏的旋律误判掉，把用户真正想弹的那条轨藏起来。

`TrackRanking` 把可演奏的轨按「最像主旋律」排序，第一条默认选中。

一条能弹的都没有时，下拉框锁死，给出明确说明和一个「去编辑器」按钮，开始按钮变灰。

### 判据（这一张的全部要害）

判的是**起音两两是否同时**：音符按起点升序，相邻两个的**秒**间隔 `≤ 30ms` 即撞。
容差是**秒不是 tick** —— 同一份谱换个 PPQ 就是另一个数，而「听起来同不同时」是耳朵的事。
取 `<=` 而不是 `<`：刚好卡在 30.000ms 的两个音，游戏那一帧多半也只读得到一个，当成能弹就是把漏音
放出去，边界往严的一侧倒。

**判据刻意不是「时值是否重叠」。** 连奏（前音未止、后音才起）时值重叠、起音不同时，**不算**多声部 ——
换成时值重叠当判据，连奏的旋律会被整条误判掉，而那恰恰是用户最想弹的那条轨，代价是他想弹的轨
从下拉框里消失了，而且他不知道为什么。所以只扫**相邻**两个：排序之后相邻间隔都超容差的话，
任意一对只会更大，一趟线性扫描就够。

### 界面那一半

下拉框的项直接来自 `TrackRanking.Of`（有音 + 非打击乐 + 单声部），**不是**列出来之后再拦一道。
`_playable[i].SongTrackIndex` 是回指原曲的唯一通道（中间筛掉过轨，下拉框下标 ≠ `song.Tracks` 下标）；
行首序号显示的是**原曲里**的号（`SongTrackIndex + 1`），好让人拿着它回编辑器里找到同一条。
`N 条轨里 M 条可演奏` 的 N 取 `song.Tracks.Count`、M 取 `_playable.Count`，不另算一遍 —— 两个真相源迟早对不上。
一条都弹不了时：下拉锁死（`IsEnabled = false`）、说明块**顶掉**提示行（两行说的是同一件事）、
「去编辑器…」可用、开始按钮变灰；「去编辑器」把自己关掉是有意的 —— 这个窗口置顶，
留着就是一块压在编辑器上面又什么都干不了的死窗口。

令牌那条由 `TokenParityTests` 项目级守着（`除Tokens_axaml外没有字面颜色值` 扫的是 `MidiPerformer.App`
下**全部** `.axaml` 与 `.cs`，`axaml里引用的每个键都有定义` 同理），所以 `PerformerWindow.axaml`
不需要为本切片单独加断言。

  构造器按契约收有序输入（MIDI 导入排过、工程文件里存的就是排好的）。本次**没有**加「破序时兜底排序」：
